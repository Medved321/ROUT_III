## 2. Окно и вывод

- [x] 2.1 `client/renderer.py`: `set_window_size((w, h))` — `set_mode` с
      `RESIZABLE`, обновление `const.W/const.H`, колбэг `on_resize`.
      `normalize_size(w, h)` — чётность (нечётные → вниз), минимум 320×200,
      потолок 7680×4320; возвращает применённый размер, а не «изменилось»:
      клиенту нужно знать, что получилось, чтобы записать это в конфиг.
- [x] 2.2 `client/renderer.py`: виртуальная поверхность меню `ui` (1000×700) +
      `present()` (масштабирование в окно с центрированием чёрным, nearest —
      меню нарисовано на пиксельной сетке, сглаживание только бы размывало) без
      `display.flip()`; `letterboxed_blit()` для замороженного кадра под паузой
      (снимок берётся один раз при входе в паузу, а не каждый кадр).
- [x] 2.3 `client/bridge.py`: `RenderBridge.set_output_surface(surface)` —
      перепривязка цели `blit` **и** пересоздание `gs.screen` под новые
      `const.W/const.H`; конструктор принимает поверхность любого размера.
- [x] 2.4 `client/client.py`: `_apply_window()` при старте и при выходе из
      настроек; нормализованное значение пишется обратно в конфиг; недопустимое
      значение из `config.json` логируется с откатом на 1000×700.
- [x] 2.5 `client/client.py`: `VIDEORESIZE` — события пересылаются
      `InputHandler.window_events` (в игре очередь вычитывает он, иначе ресайз
      теряется) и применяются **один раз за кадр**: пересоздание окна и
      полноэкранной `Surface` движка десятки раз в секунду — это и есть
      «не рисовать, пока окно тянут», но без `event.wait()`, который встал бы на
      весь asyncio-цикл вместе с сетевым вводом. Переподписка поверхности у
      моста — в `_on_window_resized`.
- [x] 2.6 `client/client.py`: все меню рисуют в `renderer.ui` и выводятся
      `present()` (лобби, настройки, редакторы, подтверждение обновления,
      пауза). Проверка: `smoke_ui.py` зелёный.
