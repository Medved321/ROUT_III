## Context

Изменение — только про редактор: признак «сплошная стена» (`LINE_FLAG_SOLID`,
`LineDef.solid`), его смысл в физике (`line_blocks()`), рендере
(`engine/sector_render.py`: `two_sided = back_sec >= 0 and not solid`) и
валидаторе (`solid` запрещён на односторонней линии) уже внесены pending-change
`sector-steps-and-solid-walls`. Аргументами признака `sector_from_contour()` не
принимает и на созданных гранях его не ставит; в экране редактора есть только
чип `сплошная`/`проём` для уже выделенной двусторонней линии. Мотивация — в
proposal.md («Why»).

Сегодня создание сектора из контура (`client/sector_editor.py`) превращает
каждую грань в двусторонний порт: `front` — внешний сектор, `back` — новый;
при равных высотах полов граница проходима и ничего не рисует, поэтому у
созданного сектора «нет стен».

## Goals / Non-Goals

**Goals:**

- Дать автору выбор границы нового сектора (порт / глухая стена) одним
  состоянием инструмента, видимым в UI и переживающим несколько созданий.
- Выставлять признак `solid` только на гранях, где он законен (двусторонних),
  и не ломать контуры соседних секторов и валидность карты.
- Оставить поведение по умолчанию прежним, чтобы существующие карты и тесты не
  менялись.

**Non-Goals:**

- Выбор стиля границы для конкретного создания и сохранение состояния в
  `config.json`.
- Односторонние грани, автоматические ступени и правки формата карт/движка.
- Изменение уже созданных секторов при переключении состояния.

## Decisions

### D1. Состояние живёт в `SectorEditor`, а не в экране

`SectorEditor.solid_on_create: bool = False` — рядом с `snap_on`, тем же
родом настройка инструмента. Экран только переключает и показывает её.
Альтернатива — поле на `SectorEditorScreen`: тогда поведение создания,
зависящее от настройки, недоступно модели и проверяется только через UI, а
логика выкладывается на два места.

### D2. Граница — двусторонняя с признаком `solid`, а не односторонняя стена

Признак сохраняет ребро в контурах **обоих** секторов: и созданного, и того, что
стоял на этих рёбрах. Односторонняя грань вытащила бы ребро из контура соседа —
его направленный обход перестаёт замыкаться, и `_ensure_polys()` молча дропает
контур: сектор-комната становится пустотой (частично ловится `has_polygon()`,
но сам эффект — потеря области, а не ошибка). Признак же уже поддержан во всех
потребителях, названных в Context, и 2D-оверлей рисует такую линию как стену
(`line_wall_kind() == "wall"`). Вариант с обводкой новой комнаты отдельными
линиями отвергнут: дублирование геометрии и лишние T-junction.

### D3. `sector_from_contour()` читает состояние сам, без нового параметра

Вызов один (экран создания), источник истины один — поле модели. Новый
параметр `solid: bool` раздваивал бы источник: вызов, забывший передать
состояние, молча создавал бы порты. Тест модели включает поведение, выставив
поле.

### D4. Кнопка в нижнем тулбаре, пересборка тем же путём, что «Сетка»

Подпись кнопки — её ширина (`fit_width`/`layout_row`), а строка переносится;
поэтому переключение обязано делать то же, что переключение «Сетка»: пересобрать
тулбар, ужать канвас на новую высоту тулбара
(`canvas.height = height - 56 - _toolbar_h - 8`) и пересобрать панель. Иначе
кнопка/панель рисуются поверх канваса, а хитбоксы расходятся с нарисованными
прямоугольниками (правило AGENTS «всё, что рисуется, и есть всё, что кликается»).
Альтернативы: кнопка фиксированной ширины (подпись не влезет); отдельное меню
настройки (лишний UI для булева).

### D5. Статус сообщает результат создания

`Сектор N создан (глухие стены)` / `Сектор N создан (проёмы)`. Статусная строка —
единственная обратная связь о том, какая граница применена; иначе включённое
состояние заметно только по 2D-оверлею.

## Risks / Trade-offs

- [Рост подписи переносит кнопку и ломает раскладку тулбара/канваса] →
  пересборка тем же путём, что у «Сетка», плюс кейд: прямоугольники тулбара не
  пересекаются и лежат ниже канваса на пресетах 1000×700…1600×900.
- [Автор запечатал проход, который хотел оставить] → состояние видно подписью и
  толстой белой линией в 2D; откат — Ctrl+Z (запись геометрии) либо чип
  `проём` на конкретной линии.
- [Глухие стены не рисуются там, где их ждут] → рисунок и проходимость идут из
  одного признака, уже проверенного change'ем `sector-steps-and-solid-walls`;
  новый код только выставляет признак, потребителей не трогает.
- [Создание сектора из границ существующей комнаты] → двусторонность сохраняет
  контуры, меняется только проходимость границы — это и есть запрошенный эффект.

## Migration Plan

Формат `.mt1`/`.mts` и протокол не меняются: признак `solid` уже сохраняется и
читается, round-trip покрыт `smoke_text_map.py` и `smoke_sector_model.py`.
Откат — убрать поле состояния, кнопку и одну строку в `sector_from_contour()`;
карты, сохранённые с признаком, читаются как раньше и требуют отката только если
нужен прежний вид границы.
