# Design: производительность на слабом железе

## Context

Клиент: asyncio-цикл `_game_loop` (`client/client.py:365`) вызывает
`_process_input` (в т.ч. `send_input`), `_update_local_state`, `_render`
(полный `rendering.render()` + `flip`) и `sleep(0.001)`. Рендер —
чистый Python: на колонку луч марширует шагом 6 px до `gs.view_dist`
(`rendering.py:1292-1323`), затем `transform.scale` на колонку.

Сервер: `_game_loop` (`server/server.py:61`) на каждом тике (20 Гц) вызывает
`_broadcast_parties` → `broadcast_world_state` (`server/network.py:304`),
которая делает `sendto` по списку адресов без обработки ошибок. Ошибки
приходят в `error_received` (`server/network.py:105`) и логируются на каждую.

## Goals / Non-Goals

- Goal: FPS на слабом ПК не деградирует до «слайд-шоу»; HUD/ввод отзывчивы.
- Goal: выход клиента не вызывает у сервера лавину ошибок и фризов.
- Goal: движение удалённых сущностей плавное при джиттере/потерях.
- Non-Goal: менять тикрейт сервера (20 Гц) и формат мира.
- Non-Goal: гарантировать 60 FPS на любом железе — только адаптацию качества.

## Decisions

1. **Бюджет кадра.** Замерять время кадра; держать целевой FPS из `fps_cap`.
   Разделить частоты: сетевой ввод — фиксированный интервал (≈1/25 c),
   рендер — по возможности. Использовать `clock.tick_busy_loop`/аналог только
   при запасе, `sleep` — при нехватке.
   - `render_scale` — стартовое/максимальное значение; при перерасходе бюджета
     (`avg_frame > 1000/target * 1.2`) увеличивать scale на 1 (снижать
     качество) до `MAX_ADAPTIVE_SCALE` (напр. 8); при устойчивом запасе
     возвращать к значению из конфига. Значение в `config.json` не менять.
2. **Развязка ввода.** `send_input` вызывать по таймеру (накопитель времени), а
   не каждую итерацию; при этом слать самый свежий снимок ввода.
   - `rotate_delta` для абсолютного угла (`local_angle`) не зависит от частоты.
3. **Дешёвые эффекты.** Кэшировать `Surface` по (тип, размер, цвет) в
   `particles`/`draw_decals` вместо создания на кадр; лимитировать число
   активных частиц/декалей (уже есть бюджеты — проверить и связать с
   качеством); окклюзию декалей считать реже (не каждый кадр / по сетке).
4. **Троттлинг ошибок сервера.** `error_received`: агрегировать по типу/адресу
   и писать не чаще, чем раз в N секунд, с счётчиком повторов; уровень —
   `debug`/`info` для ожидаемых `WSAECONNRESET` (`WinError 10054`).
5. **Недостижимые адреса.** По коду `10054` пометить `addr` как unreachable
   (множество), исключать из рассылки и инициировать удаление сессии в
   ближайшем тике (`_remove_stale_players`/отдельный список). Штатный
   ping-таймаут 10 с остаётся как предохранитель.
6. **Интерполяция снапшотов.** Хранить последние 2 снапшота с временем
   получения; рендерить удалённые сущности с задержкой `INTERP_DELAY`
   (≈1–2 тика), линейно интерполируя позиции/углы. Локальный игрок —
   без интерполяции (предсказание). При потере снапшота — экстраполяция не
   дольше `MAX_EXTRAPOLATION`, затем удержание последней позиции (без рывка).

## Risks / Trade-offs

- Интерполяционная задержка добавляет латентность визуализации удалённых
  сущностей; это стандартный обмен (как в Source/Quake) и незаметно для PvE.
- Адаптивное качество может «дёргать» картинку при колебаниях; нужен
  гистерезис (менять не чаще, чем раз в ~1 c, с порогами).
- Кэш поверхностей эффектов увеличивает потребление памяти — ограничить
  размером/числом ключей (LRU).

## Migration

Совместимо: протокол не меняется, старые клиенты продолжают работать (они просто
не умеют интерполировать). Откат — вернуть прямую отправку `send_input`.
