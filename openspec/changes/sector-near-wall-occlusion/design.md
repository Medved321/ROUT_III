# Design

## Context

`engine/sector_render.py` рисует секторный кадр в две фазы: `_walk_subsectors()`
(BSP, ближние subsector'ы перед дальними) и для каждого subsector'а —
`_seg_wall_bands()` по каждому seg. Клиппинг per-column (`clip_top`/`clip_bot`)
— прямой перенос DOOM `ceilingclip`/`floorclip`: сплошная стена закрывает
колонку (`clip_top[col] = ih; clip_bot[col] = 0.0`), двусторонняя — подтягивает
границы под верхнюю/нижнюю кромку.

Клиппер корректен только при монотонном порядке «сначала ближние, потом
дальние». Между subsector'ами этот порядок даёт обход BSP, но **внутри одного
subsector'а** `bsp.sub_segs()` возвращает segs в произвольном порядке, и никакой
гарантии у него нет. Комментарий-инвариант в `_seg_wall_bands` («walls drawn
before the current seg are always nearer») для сегментов одного subsector'а ложен.

Замеры (см. proposal.md — Why): 142 135 нарушений порядка по колонкам, ~99.9%
внутри одного subsector'а; ближайшая сплошная стена не нарисована вплоть до 37%
лучей на карте из нескольких комнат. Отдельно — `ZeroDivisionError` при
`t == 0.0` у конца сегмента.

Ограничения проекта: `engine/` автономен и импортирует только stdlib/pygame/
numpy(опц.) + `shared.sector_map`/`shared.mt1`; бюджет кадра жёсткий
(`total-performance`); правка не трогает игровые механики.

## Goals / Non-Goals

**Goals:**

- Ближайшая стена вдоль луча всегда нарисована, независимо от порядка segs
  внутри subsector'а и от угла обзора.
- Убрать падение кадра при наблюдателе ровно на конце сегмента.
- Не менять формат карт, протокол, модель карты и BSP-сборщик.
- Не добавлять в горячий цикл на кадр сверх одного массива на ширину буфера и
  одного сравнения на колонку.

**Non-Goals:**

- Полный per-pixel z-buffer стен: «сплошная стена vs сплошная стена» — источник
  бага, а не лишний функционал.
- Переупорядочивание/пересборка BSP только ради порядка segs: `ensure_bsp()`
  обязан совпадать с сохранёнными слайсами `.mt1` (`smoke_bsp_render.py`),
  сортировка поддерева сломала бы этот инвариант.
- Изменение вида не-секторного DDA-пути (`rendering.py`).

## Decisions

### 1. Источник истины окклюзии — глубина ближайшей сплошной стены на колонку

`render_scene()` заводит массив `solid_depth: list[float]` длиной `iw`,
инициализированный `+inf`. Он и есть «насколько глубоко колонка уже закрыта
сплошной стеной»; вместо необратимого закрытия клип-массивов сплошной стеной
используется это значение.

Правила в `_seg_wall_bands()` (порядок обхода segs произволен):

- **Сплошная стена (`not two`), колонка `col`:**
  - если `t >= solid_depth[col]` — колонка пропускается целиком (никакая другая
    сплошная стена не ближе), поля не трогаются;
  - иначе полоса рисуется в `[max(yc, clip_top[col]), min(yf, clip_bot[col])]`,
    затем `solid_depth[col] = t`.
  - **Клип-массивы сплошной стеной НЕ закрываются.** Это ключевой пункт: именно
    необратимое `clip_top[col]=ih; clip_bot[col]=0` дальней стеной и вытесняло
    ближнюю.
- **Двусторонняя стена:** если `t >= solid_depth[col]` — колонка пропускается
  (ближняя сплошная стена её уже закрыла); иначе выполняется существующая логика
  верхней/нижней кромки и подтягивания `clip_top`/`clip_bot`.
- **Флаты и `view_buf`** публикуются только при `t < solid_depth[col]`; при
  установке `solid_depth[col]` колонка считается закрытой для z-буфера
  спрайтов (`view_buf[col] = min(view_buf[col], t)`), сохраняя прежнюю
  семантику «глубина стены, закрывшей колонку».
- **Ранний выход** «все колонки уже закрыты» становится «во всех колонках
  `solid_depth[col] <= t`» — одна проверка по тому же диапазону `c0..c1i`.

**Почему это порядконезависимо.** Для колонки итог зависит только от минимума
`t` среди сплошных стен (устанавливается через `solid_depth`) и от вертикального
интервала, обрезанного более близкими двусторонними кромками (через
`clip_top`/`clip_bot`). Если дальняя стена обработана раньше ближней, она лишь
поднимет `solid_depth`; ближняя всё равно пройдёт (`t < solid_depth`) и
нарисуется на полный интервал, потому что клип дальняя не закрыла. Если ближняя
раньше — дальняя отсеется по `solid_depth`. Оба порядка дают ближнюю стену.

**Альтернативы.**

- *Сортировать segs subsector'а по расстоянию до глаза.* Отклонено: одного
  скаляра на seg недостаточно. Для выпуклой области, видимой снаружи, у дальней
  грани может быть вершина, ближайшая к глазу, чем у ближней грани, — тогда
  дальняя отсортируется раньше и всё равно вытеснит ближнюю в части колонок.
  Пофрагментная (per-column) истина не сводится к порядку целых segs.
- *Собирать все полосы с глубиной, сортировать их по `t` и прогонять клиппер.*
  Корректно (у каждой полосы своя точная глубина колонки), но это переписывание
  разрешения окклюзии и флатов в отдельный пост-проход и лишняя сортировка
  `O(B log B)` на кадр. Отклонено как более дорогое при том же результате.
- *Полный per-pixel z-buffer стен.* Отклонено: дороже горячего цикла, а
  решаемая задача — только сплошные стены одного subsector'а.

### 2. Отсечение у ближней плоскости при нулевой продольной координате

В `_seg_wall_bands` ветки отсечения по ближней плоскости используют строгое
`t1 < 0.0` / `elif t2 < 0.0`. При `t1 == 0.0` (глаз ровно на конце сегмента)
отсечение не срабатывает, и следующая строка делит на `t1 * tan_h` →
`ZeroDivisionError`. Исправление: сравнивать `<= 0.0` (для каждого конца
отдельно), сохранив существующий ранний выход при обоих неположительных концах.
Порядок проверок «оба конца → отбросить, иначе отсечь один» сохраняется, чтобы
не потерять уже корректные случаи `t < 0`.

### 3. Обход subsector'ов и логика проёмов не меняются

`_walk_subsectors()` и ветка двусторонней линии (кромки `upper`/`lower`,
падение в нейтральную текстуру) остаются как есть: межsubsector'ный порядок уже
ближний→дальний, а симптом касается сплошных стен. Правка локализована в
`_seg_wall_bands()` + один массив в `render_scene()`.

### 4. Регрессия — дифференциальная проверка против эталонного трассирования

Тест строит карту из нескольких subsector'ов (сетка 2×2 комнат, как в
диагностике), свипает углы и точки, зондирует перехваченный список полос
(`_draw_wall_bands` spy — приём уже есть в `smoke_sector_render.py`) и сравнивает
минимальную нарисованную глубину колонки с эталонной — «ближайшая сплошная стена
вдоль луча». Отдельный сценарий ставит игрока ровно на вершину (целые
координаты) и требует отсутствия исключения. Тест должен падать на старом коде и
проходить на новом.

## Risks / Trade-offs

- **Остаточный случай: двусторонняя кромка vs сплошная стена одного
  subsector'а.** Кромка, вытесненная дальней сплошной стеной, при произвольном
  порядке может быть потеряна (обратный случай). Это реже и визуально мягче
  (теряется узкая полоса ступени, а не стена целиком) → вынести в Non-Goals;
  замер регрессии покажет, остаётся ли такой случай на тестовых картах; при
  обнаружении — отдельный change на общий per-column z-buffer.
- **Вертикальный интервал сплошной стены берётся из `clip_top/clip_bot`,**
  которые могла подтянуть дальняя двусторонняя кромка того же subsector'а →
  возможен недорисованный край стены на стыке → тот же остаточный класс, что
  выше; проверяется тем же угловым свипом.
- **Изменение картинки секторных карт** — это и есть цель; DDA-путь не затронут,
  карты без перекрывающихся сплошных стен одного subsector'а не изменятся.
- **Производительность.** Один `list[float]` на `iw` плюс одно сравнение на
  колонку; ранний выход сохранён, лишних аллокаций на кадр нет. Замер
  `smoke_sector_perf.py`/`smoke_perf.py` должен не показать регрессии.
- **Строгий `<= 0.0`** может отсечь вырожденный сегмент, который раньше
  «проходил» и делил на ноль/рисовался мусором → это исправление, а не потеря:
  такой кадр сегодня либо падает, либо рисует неверный пиксель.
