# Proposal

## Why

На секторных картах часть стен видна только под определёнными углами: чуть
повернувшись, стена пропадает, и сквозь неё видно, что за ней. Причина — не в
отсечении по пирамиде видимости (оно корректно), а в том, что DOOM-овский
клиппер стен по колонкам **требует порядка «сначала ближние, потом дальние»**, а
сегменты внутри одного subsector'а рисуются в произвольном порядке, в котором их
вернул сборщик BSP. Дальняя сплошная стена закрывает колонку
(`clip_top[col] = ih; clip_bot[col] = 0.0`) и навсегда вытесняет более близкую
стену того же subsector'а. Обратная гарантия DOOM «subsector выпуклый, порядок
внутри не важен» верна только для наблюдателя **внутри** subsector'а; для всех
остальных он снаружи, и стенки выпуклого полигона перекрывают друг друга по
колонкам.

Замеры на пробных картах (дифференциальная проверка «ближайшая сплошная стена
вдоль луча» против того, что реально нарисовано):

- ложных отсечений по пирамиде видимости — **0**;
- нарушений порядка «дальний раньше ближнего» по колонкам — **142 135**, из них
  ~99.9% внутри одного subsector'а;
- пропущенных ближайших сплошных стен — до **37%** лучей в карте из нескольких
  комнат; в выпуклых комнатах-одиночках — доли процента. Это и есть
  «стена видна только под определёнными углами».

Второй, независимый дефект в той же функции: клиппинг у ближней плоскости
(`_seg_wall_bands`) отсекает только `t < 0.0`, а при `t == 0.0` делит на ноль и
роняет кадр с `ZeroDivisionError`. Это достижимо, когда игрок стоит ровно на
вершине сеточной карты (целые координаты). Воспроизведено на 145 комбинациях
точка/угол.

## What Changes

- **Порядконезависимая окклюзия сплошных стен.** Вместо «сплошная стена навсегда
  закрывает колонку» вводится учёт ближайшей сплошной стены по колонке
  (per-column nearest-solid depth gate): дальняя сплошная стена не может вытеснить
  ближнюю, независимо от порядка обхода segs внутри subsector'а. Внешне это
  означает: ближайшая стена вдоль луча всегда нарисована, под любым углом.
- **Корректный клиппинг у ближней плоскости.** Сегмент, у которого координата
  вдоль луча равна нулю у одного из концов, SHALL отсекаться так же, как при
  отрицательной, — без деления на ноль и без падения кадра.
- **Регрессионный тест.** Проверка согласия отрисованных стен с эталонным
  трассированием лучей на карте из нескольких subsector'ов и проверка отсутствия
  исключения при наблюдателе ровно на вершине.
- Комментарий-инвариант в `_seg_wall_bands` («клип by order implies near→far
  always»), который сегодня ложен для сегментов одного subsector'а, приводится в
  соответствие с фактическим правилом.

Не меняются: сетевой протокол, `PROTOCOL_VERSION`, формат `.mt1`, модель карты,
серверная логика. Правка — только рендер-ядро (`engine/`).

## Capabilities

### New Capabilities

- нет — дефект лежит в уже введённой (неархивированной) capability
  `renderer/sector-renderer`.

### Modified Capabilities

- `renderer/sector-renderer`: требование «Клиппинг стен по колонкам» дополняется
  порядконезависимостью для сплошных стен (ближняя стена не может быть вытеснена
  дальней); добавляется требование о корректном отсечении сегмента у ближней
  плоскости при нулевой продольной координате.

> Дельта нацелена на `renderer/sector-renderer`, который вводится
> неархивированными changes `bsp-renderer-mt1-format` и
> `sector-steps-and-solid-walls`. Этот change SHALL архивироваться **после** них,
> иначе модель применения дельт не разрешится (как и отмечено в
> `sector-steps-and-solid-walls`).

## Impact

- **Рендер-ядро**: `engine/sector_render.py` — `_seg_wall_bands()` (логика
  закрытия колонки сплошной стеной и клиппинг у ближней плоскости),
  `render_scene()` (буфер ближайшей сплошной стены по колонкам), при
  необходимости — комментарии/инварианты.
- **Тесты**: `smoke_sector_render.py` — новый регрессионный сценарий
  (угловой свип + наблюдатель на вершине); существующие сценарии остаются
  зелёными.
- **Не затрагивается**: `shared/`, `server/`, `client/`, формат карт, протокол,
  BSP-сборщик (`engine/bsp.py`).
- **Производительность**: добавление — один массив `float` длиной в число колонок
  и сравнение на колонку в уже существующем внутреннем цикле; горячий цикл не
  получает новых аллокаций на кадр сверх уже существующих клип-массивов.
- **Риск**: правка меняет видимую картинку секторных карт (это и есть цель).
  Не-секторный DDA-путь не затрагивается; карты без перекрывающихся сплошных стен
  одного subsector'а рендерятся как раньше.
