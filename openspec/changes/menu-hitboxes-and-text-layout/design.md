# design: меню — хитбоксы и вёрстка текста

## Контекст

Меню рисуются в `Renderer.ui` — фиксированном холсте `1000×700`
(`SCREEN_WIDTH`/`SCREEN_HEIGHT`) — и выводятся в окно через `Renderer.present()`:

```python
size = self.screen.get_size()
if size == (SCREEN_WIDTH, SCREEN_HEIGHT):
    self.screen.blit(self.ui, (0, 0))
    return
dst_w, dst_h = self._letterbox_fit(size)          # scale = min(w/1000, h/700), int()
self.screen.fill(LETTERBOX)
self.screen.blit(pygame.transform.scale(self.ui, (dst_w, dst_h)),
                 ((size[0] - dst_w) // 2, (size[1] - dst_h) // 2))
```

Экраны (`connect_screen`, `lobby_screen`, `settings_screen`, `pause_screen`,
`editor_screen`, `sector_editor_screen`) при этом hit-тестятся в координатах
холста, а получают сырые pygame-события, чей `event.pos` задан в пикселях окна.
Обратного преобразования нет нигде — это и есть причина «плавающих» хитбоксов.

## Решения

### 1. Единая точка истины для геометрии вывода

Масштаб и смещение вычисляются только в `Renderer`; экраны и клиент получают
готовую пару. Добавляем инверсию `_letterbox_fit` рядом с ним, а не
дублируем арифметику в `client.py`:

```python
def canvas_rect(self) -> pygame.Rect:
    """Where the menu canvas actually lands inside the window."""
    size = self.screen.get_size()
    dst_w, dst_h = self._letterbox_fit(size)
    return pygame.Rect((size[0] - dst_w) // 2, (size[1] - dst_h) // 2, dst_w, dst_h)

def to_canvas_pos(self, pos) -> tuple[float, float] | None:
    dst = self.canvas_rect()
    if dst.w <= 0 or dst.h <= 0 or not dst.collidepoint(pos):
        return None                       # black bars: hits nothing
    return ((pos[0] - dst.x) * SCREEN_WIDTH / dst.w,
            (pos[1] - dst.y) * SCREEN_HEIGHT / dst.h)
```

Важно: использовать ровно `dst_w`/`dst_h` из `_letterbox_fit`, а не исходный
`scale`. Там стоит `int()`, поэтому масштаб получается усечённым, и при
`int()`-расхождении рамка в 1 px разъезжается с подписью.

При `size == (1000, 700)` путь вырождается в тождество — отдельная ветка
`_letterbox_fit` уже даёт `dst == (1000, 700)`, так что формула покрывает и
родное разрешение, но быстрый выход для него оставляем ради ясности.

### 2. Перевод событий — в одном месте, только для меню

`GameClient` получает один помощник, который возвращает копию списка событий с
переписанным `pos` (события без позиции — колесо, клавиши — не трогаем;
события, ушедшие за пределы холста, помечаем через `pos=None`, и экраны обязаны
их игнорировать):

```python
def _menu_events(self, events):
    out = []
    for ev in events:
        if getattr(ev, "pos", None) is None:
            out.append(ev); continue
        mapped = self.renderer.to_canvas_pos(ev.pos)
        if mapped is None:
            continue                       # клик в чёрных полях -> ничего
        e = pygame.event.Event(ev.type, ev.dict, ...)
```

`pos=None` вместо отбрасывания события выбран сознательно: `MOUSEBUTTONDOWN`
вне холста не должен, например, «съесть» фокус поля. Отбрасывание целиком
проще и безопаснее, поэтому по умолчанию событие отбрасывается, а
`collidepoint`-ветки в экранах дополнительно проверяют `None`.

Критично: перевод применяется **только** к меню. `InputHandler` (обзор мышью,
`_grabbed`, `get_rel`) работает в пикселях окна и не переводится — 3D-сцена
живёт в координатах окна. Список мест перевода: пять вызовов `screen.handle()`
в `client.py` (connect/lobby/редакторы/settings/pause).

### 3. Хитбокс = нарисованный прямоугольник

Сейчас часть экранов рисует по одному набору прямоугольников, а hit-тестит по
другому (в `settings_screen` — `_row_rect()` при прокрутке, стрелки считаются
`_left_arrow`/`_right_arrow`). Инвариант: любой прямоугольник, участвующий в
hit-тесте, берётся из того же поля/метода, что и отрисовка. Проверяется
одним тестом, который сравнивает геометрию до и после `draw()`.

### 4. Нижние панели: ширина из подписи, перенос на ряд

`pygame` не умеет мерять текст без создания `Surface`, но `font.size()` дёшево и
не аллоцирует поверхность. Вводим общий помощник:

```python
def fit_width(text, font, pad) -> int      # font.size(text)[0] + 2*pad
def ellipsize(text, font, max_w) -> str   # обрезка с '…' по font.size()
```

Нижняя панель секторного редактора (10 кнопок, сейчас 1058 px при холсте
1000 px) перестаёт быть списком чисел: кнопки выкладываются слева направо
как `x = cursor; cursor += fit_width(label) + GAP`, а при нехватке места
(`cursor + w > SCREEN_WIDTH - MARGIN`) — переносятся на следующий ряд, и
`canvas`/`panel` пересчитываются под число рядов. То же для панели
`editor_screen` (сейчас кончается на 988 px из 1000 — впритык).

### 5. Текст не выходит за рамку

- Подпись кнопки: `ellipsize` под ширину кнопки минус `2*pad`.
- Значение поля ввода: обрезка по правой границе поля с ведущим многоточием
  (показываем хвост введённого, а не начало) — в `connect_screen` поле шириной
  400 px, строка 48 символов даёт 528 px.
- Значение строки настроек: полоса значения задаётся явно
  (`rect.right - ARROW_ZONE - GAP ..`), значение усекается до её ширины.
  Сейчас полоса не задана вовсе, и `3840×2160` (108 px) заезжает на стрелку
  `<` (710..744 при правом крае строки 860).
- Сообщения и подписи полей получают собственные полосы: полоса под подпись
  поля `Ш×В` выносится из-под области прокрутки строк, полоса под ошибку —
  между полем и кнопкой «Назад», с увеличением зазора по необходимости, а не
  поверх неё.

### 6. Проверка инвариантов

Новый `smoke_menu_layout.py` (без участия игрока, через `SDL_VIDEODRIVER=dummy`):

1. Для каждого экрана: попарное `colliderect` по всем кнопкам/полям/строкам
   → 0 пересечений; объединение ⊂ холста.
2. Отрисовка каждой подписи/значения проверяется на попадание в свою рамку
   (сравнение `font.size` с размером рамки) → все помещаются.
3. Клик в визуальный центр нарисованного элемента: позиция окна считается через
   `Renderer.to_canvas_pos` в обратную сторону, событие прогоняется через тот же
   путь, что и в игре, и активируется именно этот элемент — при 640×480,
   1000×700, 1600×900 и 3840×2160.
4. Клик в чёрное поле не активирует ничего.

Остальные тесты: `smoke_ui.py` и `smoke_sector_editor_screen.py` уже подставляют
свои координаты — после перевода их надо обновить, иначе они начнут проверять
не тот путь. `smoke_resolution_controls.py` кликает в `(0, 0)`, что в холсте
остаётся валидной точкой, поэтому, вероятно, потребует правки только если
проверка начнёт требовать попадание в элемент.

## Альтернативы, отклонённые

- **Холст во весь размер окна, без масштабирования.** Убирает проблему, но
  возвращает зависимость вёрстки от габаритов и ломает требование
  «меню не зависят от размера окна» из `client/display-resolution`.
- **`pygame_gui`/готовые виджеты.** Внешняя зависимость ради ~10 экранов и
  чужое оформление; проект держится на stdlib + pygame.
- **Таблица «исключений» в клиенте** (руками перечисленные экраны и их
  геометрия). Работает, но правило «хитбокс = нарисованный прямоугольник»
  проверяется только тестом, а инверсия в `Renderer` автоматически покрывает
  любой будущий экран.
- **Клавиатурная навигация как замена мыши.** Не решает задачу: игнорировать
  мышь в меню нельзя, кнопки и списки — привычный интерфейс.

## Риски

- Расхождение масштаба отрисовки и обратного пересчёта: лечится тем, что обе
  операции берут `dst_w`/`dst_h` из одного `_letterbox_fit` (см. п. 1), плюс
  п. 3.6 теста с обратным отсчётом.
- Перенос нижней панели на два ряда меняет высоту `canvas` в секторном
  редакторе, а с ней — все производные прямоугольники. Вычислять их от
  результата раскладки, а не от константы.
- Обрезка текста меняет вид подписей: длинные значения становятся
  `3840×21…`. Это предпочтительнее наезда на стрелки, но заметно — отмечено в
  требованиях как «явно усечённо».
