# Design: infighting врагов

## Context

Враги — словари в `GameWorld.enemies` с полями `id`, `x`, `y`, `hp`, `a`
(жив), `alert`, `pa` (угол), `ls` (последний выстрел), `d_flash`. Снаряды
хранятся в `GameWorld.bullets`; вражеский снаряд содержит `'src': en['id']` и
`from_player` отсутствует/False (`server/game_world.py:280-290`). Игроцкий
снаряд содержит `from_player=True` и `src` = eid игрока.

Сейчас:

```
_resolve_enemy_ball(b)  -> только игроки (game_world.py:346)
_resolve_player_ball(b) -> враги, затем игроки-не-автор (game_world.py:362)
_update_enemies         -> target selection только среди игроков (game_world.py:190)
```

`_damage_enemy(world, en, dmg, shooter_name='')` (`server/weapons.py:95`) уже
корректно убивает и вызывает `world.kill_enemy`.

## Goals / Non-Goals

- Goal: снаряд врага ранит другого врага (кроме стрелка).
- Goal: раненый враг контратакует обидчика; смерть от infighting штатная.
- Non-Goal: менять PvP-логику игроков.
- Non-Goal: делать infighting обязательным для баланса (это эмерджентное
  поведение).

## Decisions

1. **Момент проверки — `_resolve_enemy_ball`.** После перебора игроков, если
   попадания нет, пройти по `self.enemies` и найти цель в радиусе
   `ENEMY_RADIUS + 4` (как для игроков в `_resolve_player_ball:367`), исключая
   `e['id'] == b.get('src')`. При попадании — `_damage_enemy(self, e, b['dmg'])`
   и пометить «обидчик».
   - Порядок важен: игроки приоритетнее в пределах кадра? Нет — важен ближайший
     по расстоянию. Для простоты и предсказуемости: сначала проверяем игроков
     (как раньше), затем врагов; это сохраняет прежнее поведение при равном
     кадре и добавляет infighting.
2. **Поле обидчика и таймер.** Добавить врагу `attack_from` (id врага) и
   `attack_ticks` (сколько тиков удерживать цель). При уроне:
   `en['attack_from'] = b['src']`, `en['attack_ticks'] = INFIGHT_TICKS`,
   `en['alert'] = True`. Также будить соседей в `ENEMY_ALERT_AOE`.
   - Альтернатива: искать обидчика по позиции снаряда — сложнее и хрупко;
     id надёжнее.
3. **Выбор цели.** В `_update_enemies` до перебора игроков проверить
   `attack_from`: найти врага по id; если жив, `attack_ticks > 0` и в
   `ENEMY_DETECT_RANGE` (+ LOS) — выбрать его целью и уменьшать `attack_ticks`.
   Иначе сбросить `attack_from` и перейти к обычному выбору.
   - Меле-атака: обобщить блок ближнего боя так, чтобы цель-враг тоже получала
     урон (сейчас блок работает только с `target_eid` игрока,
     `game_world.py:246-258`). Ввести универсальную пару (позиция, применить
     урон), либо отдельную ветку для enemy-target.
4. **Самоурон исключён.** Снаряд врага не может ранить стрелка (проверка по
   `src`). Дружественный огонь по «своим» не отключён (как в Doom).
5. **Смерть.** `kill_enemy(en)` создаёт труп; логика `dying`/`a` уже
   поддерживается. Кредит убийства игроку не начисляется (killer='').

## Risks / Trade-offs

- Возможны цепочки «все дерутся со всеми» в плотных группах. Это ожидаемое
  Doom-поведение; при необходимости ограничивается `INFIGHT_TICKS` и радиусом.
- Дополнительный перебор врагов в `_resolve_enemy_ball` — O(E) на попадание;
  приемлемо (E невелико), но при больших картах стоит ограничить проверку
  ближайшим кандидатом.
- Не забыть, что `get_enemy_states` не передаёт `attack_from` клиенту — для
  визуала не требуется (клиент рисует направление `pa`), менять протокол не
  нужно.
