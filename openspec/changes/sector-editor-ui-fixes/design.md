# Design

## Почему сброс выделения — в функции отрисовки, а не в каждом месте

Источников «массивы перестали соответствовать выделению» будет больше, и они
добавляются по мере развития редактора: загрузка карты, удаление лайндефа,
удаление вершины, расформирование сектора, отмена и повтор. Ловить каждый
источник в месте его появления — значит каждый раз забыть один.

Поэтому проверка вынесена в `_sync_sel()` и вызывается из `draw()`: это
единственная точка, через которую проходит любое состояние выделения перед тем,
как оно будет прочитано. Сброс в конкретных местах (`_load`, `_load_mts`) —
вторая линия обороны: состояние корректно сразу после операции, а не только к
следующему кадру, что важно для кода, читающего выделение между кадрами
(обработчики событий).

Сама проверка тривиальна: для каждого поля — сравнение с `len()` соответствующего
массива модели. Ничего не «восстанавливается» (индекс нельзя перенести на
другую карту), протухшее поле просто обнуляется — ровно как это уже делает
`_set_sel()` без аргументов.

## Порядок отрисовки

`draw()` рисует слои в порядке «сзади — вперёд»:

```
fill(BG) → title → map picker (хром) → canvas → panel → buttons → status
```

Выпадающий список — это не часть фона, а всплывающий элемент поверх канваса,
поэтому он обязан рисоваться последним. Вынесение в `_draw_map_dropdown()`
(а не просто перестановка строк) нужно затем, что хром и всплывающий список
имеют разную природу: хром — постоянная часть верхней панели, список —
условный. Их разделение позволяет рисовать хром там же, где и раньше, и не
ломать позиционирование.

Проверка попадания по строке (`_map_rows`) не меняется: прямоугольники
вычисляются из тех же координат, что и раньше. Но её **порядок** должен
зеркалить порядок отрисовки: раньше `canvas.collidepoint()` проверялся первым,
а список открывается поверх канваса, поэтому клик по строке уходил в
`_canvas_left_down()`, а блок закрытия списка по промаху был недостижим для
кликов по канвасу. Теперь имя поля, кнопка списка, затем строки списка и
только потом канвас. Побочный эффект, совпадающий с изначальным намерением
кода: клик по канвасу при открытом списке закрывает список, а не попадает в
канвас.

## Ограничение высоты списка

Высота строки — 22 px (`MAP_ROW_H`), список открывается под кнопкой
(`map_list_btn.bottom + 6`). Доступная высота считается от `y` до нижней кромки
окна с запасом в 8 px:

```
max_rows = max(1, (self.height - 8 - y) // MAP_ROW_H)
```

Показываются первые `max_rows` файлов, а если остались ещё — под последней
строкой рисуется строка «…ещё N» той же высоты (в расчёт высоты рамки она входит,
но в `_map_rows` не попадает и по ней нельзя кликнуть, чтобы не открыть
несуществующую карту). Сортировка уже есть в `_scan_map_files()`, поэтому
«первые N» — детерминированный порядок из `sorted(os.listdir(...))`.

Константа `MAP_ROW_H = 22` вводится вместо магического числа, которое сейчас
повторяется в трёх местах (смещение, шаг, радиус рамки).
