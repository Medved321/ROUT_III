## Why

Секторные карты живут в бинарном `.mt1` (WAD-подобный контейнер) и в JSON.
Ни то, ни другое не читается человеком: `.mt1` — байтовый контейнер с
каталогом срезов, JSON требует знаний индексов и структуры данных. Формат,
который можно написать и понять в любом текстовом редакторе (включая
блокнот), без знания Python и без ручной нумерации сущностей, делает карты
доступными автору без инструментов редактора и служит понятным «исходником»
рядом с `.mt1`. Лёгкий парсер превращает этот текст в обычную модель
`SectorMap`, а та уже умеет сериализоваться в `.mt1` для сети и движка.

## What Changes

- **Новый текстовый формат секторных карт** (расширение `.mts` — "map
  text sector", читаемый в блокноте): русскоязычные ключевые слова, комнаты
  задаются списком углов, вершины/линии/стороны/сектора строятся парсером
  автоматически (без индексов). Полная модель механик — текстуры сторон
  (upper/mid/lower), свет, теги и спец-поля линий/секторов, вещи.
- **Парсер в `shared/`** (stdlib-only, без numpy/pygame): текст → `SectorMap`
  → `to_mt1()` для сети/движка; обратно движок/редактор могут сохранить
  `.mt1` в `.mts`. Ошибки — понятные русские сообщения («комната не
  замкнута», «угол дублируется», «нет игрока»).
- **Честное разделение «реализовано / резерв»**: сегодня в игре работают
  текстуры, свет, спавн игрока, геометрия и проёмы; `special/tag`,
  триггеры-рычаги, двери-механики, враги/предметы из карты — это полные
  данные модели (транспортируются в `.mt1`), а их серверная обработка —
  резерв (поле доступно, поведение — будущим change).

## Capabilities

### New Capabilities
- `map/text-format`: текстовый человекочитаемый синтаксис секторных карт
  (`.mts`), автоматическое построение геометрии из комнат, полная модель
  механик как данных, конвертация в/из `SectorMap`/`.mt1` с понятными
  ошибками.

### Modified Capabilities
- (нет: `map/sector-format` и `renderer/sector-renderer` не меняют семантику;
  формат — альтернативный вход, ведущий в ту же `SectorMap`)

## Impact

- `shared/`: новый stdlib-модуль парсера (напр. `shared/text_map.py`) —
  функция/класс: `parse(text) -> SectorMap`, `render(map: SectorMap) -> str`;
  без единственной зависимости кроме `shared.sector_map`.
- `tools/build_client.py`: пакету `shared/` новый модуль включается
  автоматически (пакет копируется целиком) — правок нет.
- Редактор: кнопка «Открыть .mts»/«Сохранить .mts» (импорт/экспорт),
  не трогая внутренний формат редактора.
- Тесты: `smoke_text_map.py` (парсинг, round-trip, ошибки), регрессия
  секторных `.mt1`.
- Сервер не меняется: принимает уже готовый `.mt1` (через `SectorMap`);
  текстовый парсер — клиентская/авторская утилита в `shared`.
