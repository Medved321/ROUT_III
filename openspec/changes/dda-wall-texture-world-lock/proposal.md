# Proposal

## Why

Текстура стены в тайловом (DDA) режиме не привязана к миру: при движении и
повороте игрока линии пикселей стены «уезжают» вдоль стены, вместо того чтобы
оставаться на своих мировых местах. Тексель берётся не из точки попадания, а из
**первого шага луча, уже находящегося внутри стены**: DDA идёт с шагом `d += 6`,
поэтому `hit_x/hit_y` — это точка, перелётёвшая плоскость стены на 0..6 единиц,
и чем скользящий луч, тем дальше. `tex_x` считается именно из неё.

Измерено симуляцией пути (`rendering.py:947-968`) на комнате 9x8 тайлов:

- **204 из 320 лучей** берут не тот тексель, который соответствует истинной
  точке на плоскости стены; хвост ошибки — до **32 текселей** (половина
  текстуры);
- один и тот же **мировой** пункт стены из двух соседних точек стояния даёт
  разные тексели: `y=260.68 -> 4` против `y=259.51 -> 3`, `y=330.09 -> 10`
  против `y=330.79 -> 11`;
- ошибка зависит от фазы шага `d += 6`, то есть меняется при каждом шаге и
  повороте игрока — картинка «плывёт» вместо того, чтобы стоять на месте.

Это ровно наблюдаемое «стена всегда повёрнута к игроку»: мировая привязка
есть в формуле, но она размыта перелётом, зависящим от игрока.

Секторный (BSP) путь и вторая, упрощённая ветка стен уже считают `tex_x` из
мировых координат вдоль линии (`sector_render.py:731`, `rendering.py:754-715`),
то есть правильная привязка в проекте есть — расходится только DDA.

## What Changes

- **`tex_x` в DDA считается из точного пересечения луча с плоскостью тайла, а
  не из точки перелёта.** Плоскость — та граница, которую луч пересёк между
  предыдущим и текущим тайлом; пересечение считается аналитически. Фаза
  текстуры сохраняется: `tex_x = 0` по-прежнему на нижней границе тайла.
- **`hit_x/hit_y` получают то же точное значение** — они нигде, кроме `tex_x`,
  не читаются (`rendering.py:942-966`), поэтому правка локальна.
- **`d`, `rd`, `z_b`, клиппинг и проекция не меняются.** Глубина остаётся
  дискретной (шаг 6), как была: изменение расстояния сдвинуло бы границы
  окклюзии, а это другая задача и другая цена.
- `c`/`s` делятся только в ветке, где соответствующая компонента гарантированно
  ненулевая (пересечение границы по X требует `cos(ra) != 0`), плюс защита от
  вырожденного значения.

## Impact

- `engine/rendering.py` — участок DDA стен (строки 960-966).
- Новый smoke `smoke_dda_wall_texture.py`: текстурная привязка проверяется по
  кадру, а не по копии формулы.
- Визуально: на тайловых картах текстура стены перестаёт «плыть» при ходьбе и
  повороте; ошибка текселя на луче падает с десятков до нуля.
- Протокол, формат карт, секторный рендер и граница движка не затронуты.
