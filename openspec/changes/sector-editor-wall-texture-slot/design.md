## Context

Палитра текстур стен (`client/sector_editor_screen.py`) показывает чипы сторон
(`ПЕРЕД`/`ЗАД`) и слотов (`НИЗ`/`ВЕРХ`) и сетку имён `WALL_TEXTURE_ORDER`, а
запись делает `SectorEditor.set_side_tex(side, target, name)`. Слот `mid`
поддержан моделью, форматом и рендером:

- `shared/sector_map.SideDef` хранит `upper`/`mid`/`lower`, round-trip `.mt1`
  покрыт `smoke_text_map.py`;
- `engine/sector_render.py` рисует `mid` для сплошной стены и губы `upper`/
  `lower` для двустороннего порта;
- `client/bridge.py` берёт имя текстуры стены через `gs.tile_provider`.

Мотивация — в `proposal.md` («Why»).

## Goals / Non-Goals

**Goals:**

- Дать автору назначать основную текстуру стены (`mid`) из того же места, где уже
  назначаются губы, — без нового экрана.
- Сделать так, чтобы клик по палитре менял **видимую** поверхность: цель по
  умолчанию совпадает с тем, что рендер рисует для выделенной линии.
- Не менять формат карт, протокол и рендер.

**Non-Goals:**

- Односторонние линии (см. proposal «Non-goals»).
- Автоподбор слота по геометрии секторов.

## Decisions

### D1. `mid` — чип в той же палитре, а не отдельный блок

Палитра уже владеет «какую текстуру куда писать» — сторона плюс слот. `mid` —
это просто третий слот (`TEX_CHIP_NAMES`), и добавление ключа подключает его к
существующим путям отрисовки и клика без новых кнопок. Альтернатива — отдельный
блок «основная текстура» — дублировала бы сетку `WALL_TEXTURE_ORDER` и её
hit-боксы, а «всё, что рисуется, и есть всё, что кликается» требует двух владельцев
одной сетки не заводить.

### D2. Ширина чипа считается из их числа

`_build_tex_palette()` задавала `cw = (w - 12) // 4`; пятый чип вышел бы за
панель, а нарисованный прямоугольник и есть зона клика — чип перестал бы
нажиматься. Ширина теперь `max(28, (w - (n - 1) * 4) // n)` при
`n = len(TEX_CHIP_NAMES)`: пять чипов по 51 px укладываются в `w = 284 - 12 = 272`
и не тонут в `_fit()` (подпись «СТЕНА» у моно-шрифта 12 короче 51 px). Тулбар
подписи уже переносит через `layout_row`/`fit_width` — это правило палитры, а не
тулбара.

### D3. Дефолт цели — от самой линии, а не глобальная константа

`_set_sel()` при выделении линии ставит `_tex_target = "mid"` для сплошной стены
(`lines[i].solid`) и `"lower"` для двустороннего проёма. Это ровно те поверхности,
что рисует `engine/sector_render.py` в каждой ветке, поэтому «выбрал линию →
кликнул текстуру → увидел изменение» работает без знания автора о слотах.
Глобальный дефолт `"mid"` не годится: у проёма `mid` не рисуется вообще, и автор
снова получил бы «ничего не меняется». Чип остаётся — слот можно задать вручную
(например, тектировать губу, а не основную поверхность).

### D4. Односторонние линии вне объёма

`_tex_side_idx()` возвращает `None` для односторонней линии (у неё одна сторона),
поэтому палитра для неё не рисуется вовсе. Это отдельная правка (показать палитру
со стороной `front` и целью `mid`), и она не нужна, чтобы закрыть основную
жалобу: контурные комнаты дают двусторонние грани. Объявлено Non-goal.

## Risks / Trade-offs

- [Пятый чип уезжает за панель и перестаёт кликаться] → ширина из числа чипов;
  тест `_check_tex_palette` проверяет `panel.contains(_tex_chips["mid"])`.
- [Дефолт `mid` на не-сплошной линии возвращает «ничего не меняется»] → дефолт
  зависит от линии: `mid` только у `solid`, `lower` у проёма (D3).
- [Существующий тест ждёт дефолт `lower`] → он выделяет двусторонний проём, и
  дефолт для него прежний (`lower`); новый сценарий добавляет сплошную стену и
  проверяет `mid`.

## Migration Plan

Формат `.mt1`/`.mts` и `PROTOCOL_VERSION` не меняются: `mid` уже сохраняется,
читается и валидируется. Откат — убрать ключ `mid` из `TEX_CHIP_NAMES`, вернуть
`cw`/дефолт и снять новый сценарий теста; карты, у которых `mid` задан, читаются
как раньше.
