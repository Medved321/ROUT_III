# Design: выбор карты в лобби

## Context

Карта для новой партии сейчас приходит только из редактора: F5 сохраняет
`.mt1`, кладёт `SectorMap` в `GameClient.custom_sector_map` и возвращает игрока
в лобби, где имя карты лишь подписано в нижней полосе. В лобби нет ни списка
карт, ни действия выбора; `C` только обнуляет три поля. Запрос игрока —
выбирать ту же карту сразу в лобби, без похода в редактор.

Ограничения, которые задают решение:

- меню рисуются в фиксированном холсте 1000×700 и получают события уже в
  координатах холста (`GameClient._menu_events`); хитбокс обязан совпадать с
  нарисованным прямоугольником;
- нижняя часть лобби уже занята двумя рядами кнопок и тремя текстовыми полосами
  (`bottom_bands()`), поэтому новый элемент не может просто добавить четвёртую
  кнопку в верхний ряд — это перенесёт нижний ряд за границу холста;
- протокол `CREATE_PARTY` уже умеет нести `.mt1` и флаг `MAP_FORMAT_SECTOR`;
  сервер проверяет карту через `SectorMap.validate_network`;
- карты лежат в `maps/` как пары `.mts`/`.mt1`, причём редактор показывает
  имена без расширения и при выборе читает `.mts`.

## Goals / Non-Goals

**Goals:**

- один список карт для редактора и лобби, без дублирования правил расширений;
- один владелец выбранной карты в клиенте — и для F5, и для выбора в лобби;
- выбор карты мышью, клавиатурой и тапом, с явной ошибкой на битом файле;
- явный сброс и отсутствие сохранения между запусками.

**Non-Goals:**

- новые поля протокола, новые типы пакетов, изменение серверной логики;
- выбор тайловых `.json`-карт в лобби (они остаются легаси-совместимостью);
- редактирование карты из лобби, загрузка карт по сети;
- наблюдение за каталогом без открытия списка (список читается при
  каждом открытии, что дешевле слежения за файлами).

## Decisions

### 1. Каталог карт — отдельный модуль

Новый `client/map_library.py` владеет:

- расположением каталога (`MAPS_DIR`), которое тесты переприсваивают так же,
  как сейчас переприсваивают `client.sector_editor_screen.MAPS_DIR`;
- `list_map_names()` — отсортированный список имён без расширения из `.mts`
  и `.mt1`, с дедупликацией по имени;
- `load(name)` — читает `.mts`, если он есть, иначе `.mt1`; перед чтением
  проверяет `os.path.basename(name) == name` и отсутствие разделителей, чтобы
  имя из UI не могло выйти за каталог;
- валидацией: для `.mt1` — `SectorMap.validate_bytes(data)`, для `.mts` —
  `text_map.load(..., validate=True)` и последующая проверка полученных
  `.mt1`-байтов тем же `validate_bytes`. Возвращается `(name, payload, errors)`.

`client/sector_editor_screen.py` использует `list_map_names()` вместо своего
`_scan_map_files()` и `load()` вместо прямого чтения `.mts` из строки имени.
Это убирает расхождение «в списке есть `.mt1`, а по клику — “не найдено”».

Альтернатива — оставить сканер в экране редактора и скопировать его в лобби —
отвергнута: два списка расширений и два правила дедупликации неизбежно
разъедутся.

### 2. Один владелец выбранной карты

`GameClient` вместо трёх полей `custom_map` / `custom_sector_map` /
`custom_map_name` получает одно поле `map_selection` с полями `name` и `payload`
(байты `.mt1`). Отображаемое имя в `LobbyScreen` — проекция этого поля через
`set_custom_map(name, error=...)`; имя в лобби нужно только для показа и сброса,
а не как второй источник карты.

- выбор в лобби: `map_library.load(name)` → payload → `map_selection`;
- F5 в редакторе: `sm.to_bytes()` → payload → `map_selection` (имя из поля
  редактора);
- `C` / «без карты»: `map_selection = None`;
- создание партии: если `map_selection` есть, отправляются её байты и
  `MAP_FORMAT_SECTOR`, иначе — обычный `CREATE_PARTY` без карты.

Никакого повторного чтения файла в кадре или при создании партии: файл мог
исчезнуть после выбора, а партия должна получить уже проверенную карту.
Легасная ветка `custom_map` (тайловые карты) в клиентском UI недоступна и
удаляется из пути создания партии; сетевой тест `smoke_custom_map.py`,
проверяющий напрямую `NetworkClient.send_create_party` с тайловой картой,
остаётся без изменений.

### 3. Геометрия лобби

Новый элемент — кнопка «Карты» в правой части нижней полосы карты. Её прямо-
угольник считается один раз в `LobbyScreen` и используется и для `draw()`, и для
`handle()`. Текст выбранной карты усекается по ширине полосы минус кнопка и
отступ; статус и подсказки остаются в своих полосах и не двигаются под кнопки.

Выпадающий список открывается **вверх** от кнопки (до неё мало места, внизу —
подсказки): строка «без карты» плюс имена карт. Высота списка ограничена
свободным местом до верха холста; при избытке показывается строка «…ещё N»,
а колесо/свайп двигают окно списка. `handle()` при открытом списке первым
проверяет его строки и только потом кнопки лобби, поэтому нарисованный оверлей
и есть активная зона. Клик по строке «без карты» возвращает `clear_map`, по
строке карты — `map:<name>`; клик мимо закрывает список.

Альтернатива — отдельный экран выбора — отвергнута: для одного действия
«выбрать карту перед созданием» она добавляет переход и не решает задачу
«быстро выбрать из лобби».

### 4. Ошибки вместо тихого отказа

`map_library.load()` никогда не бросает наружу: он возвращает список ошибок.
Клиент при ошибке оставляет прежний `map_selection`, а в лобби показывает
сообщение в полосе карты (`set_custom_map(current_name, error=...)`), чтобы
статус сети не затирался. Имя из файловой системы не попадает в протокол без
успешной валидации.

### 5. Тесты как часть контракта

- `smoke_lobby_map_picker.py`: дедупликация имён, приоритет `.mts`, битая карта
  не меняет выбор, клик по строке → `CREATE_PARTY` с секторным флагом, `C`
  и «без карты» → партия без карты, F5 → тот же выбор, новый `GameClient` не
  наследует выбор.
- `smoke_menu_layout.py`: кнопка выбора добавляется в список элементов, её
  центр и центр строки списка попадают в нужный элемент на 640×480 … 3840×2160,
  длинное имя усекается, полосы не пересекаются.
- `smoke_custom_map.py` обновляется под единое поле выбора; регрессии
  `smoke_mt1_party.py`, `smoke_sector_editor_screen.py`, `smoke_ui.py`.

## Risks / Trade-offs

- [Файл карты изменился между открытием списка и выбором] → payload читается и
  проверяется в момент выбора, затем хранится в памяти; в партию уходит именно
  он.
- [Список открыт поверх списка партий] → строки списка карт проверяются первыми
  и рисуются последними; клик мимо строк закрывает оверлей.
- [Большая карта не влезает в надёжный канал] → используется существующая
  проверка `SectorMap.validate_bytes`; сервер всё равно отклоняет невалидные
  байты, как и для редакторского пути.
- [Отказ от `config.json`] → выбор живёт до перезапуска, как решил игрок; F5
  и лобби не пишут конфиг.

## Migration Plan

Изменение затрагивает только клиент и тесты. При откате возвращаются старые
поля `custom_*`, вёрстка лобби и собственный сканер редактора; протокол и
сервер остаются совместимыми на любом шаге. Файлы в `maps/` не меняются.

## Open Questions

Нет. Место в UI, источник карт и срок жизни выбора зафиксированы ответами
игрока до создания change.
