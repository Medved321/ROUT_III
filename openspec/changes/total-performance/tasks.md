## 3. Перспективные флаты (`client/render-backend`)

- [x] 3.1 `client/engine/np_flats.py`: предрасчёт офсетных карт `u_off/v_off`
  по горизонта, выборка текстур флатов через `np.frombuffer` reshape +
  индексные карты, применение света. Проверка: юнит сверяет строку пола с
  по-пиксельным эталоном (допуск 1-2 уровня из палитры).
- [x] 3.2 numpy — обязательная зависимость клиента с автоустановкой при
  запуске: модуль бустрапа (проверка импорта до pygame/меню), при отсутствии —
  сообщение «Установка numpy…» и `sys.executable -m pip install --user numpy`
  через subprocess, повторный импорт; успех → обычный запуск, неудача → явное
  сообщение и выход; включение numpy в zipapp через `tools/build_client.py`.
  Проверка: (а) запуск без numpy с разрешённой установкой — numpy ставится и
  клиент продолжает запуск; (б) подмена импорта с недоступным pip/сетью —
  понятное сообщение и корректный выход без «тихого» упрощённого рендера;
  (в) запуск с уже установленным numpy — без инициации установки; (г) собранный
  артефакт содержит numpy и запускается без внешней установки.
- [x] 3.3 Интеграция флатов в `framebuffer.py` по колонкам/строкам (перспектива
  по глубине строки, клиппинг по `clip_top/clip_bottom` из секторного рендера).
  Проверка: флаты не закрашивают стены; на ступенях/окнах корректно.

  адаптация тира/лимитов; единый вызов из всех экранов. Проверка: mimic-нагрузка
  сдвигает тир вверх/вниз без флаппинга (тест-скрипт).
- [ ] 4.2 Метрики: `gs.metrics` (FPS, длительность, тир, IW×IH, спрайты/частицы,
  срабатывания адаптации), обновление ~1 раз/с, вывод логом и экранной накладкой
  по горячей клавише, накладные <1% кадра. Проверка: накладка не двигает FPS
  свыше 1%.
- [ ] 4.3 Редактор и лобби под бюджетом: снижение деталей канваса редактора
  (сетка, оверлеи), в лобби — статичная подложка вместо анимации при просадке.
  Проверка: на слабой машине редактор с тысячами линий держит бюджет; лобби не
  теряет кликабельность.

## 5. Эталон, бенчмарк и регрессия

- [ ] 5.1 `tools/perf_bench.py --map ... --seconds 30 --out results.json`:
  FPS, p95 кадра, тир, число адаптаций; запуск на эталонной машине; README —
  описание эталонной машины и инструкция по бенчмарку. Проверка: бенчмарк
  запускается на тайловой и секторной картах и пишет JSON.
- [ ] 5.2 Регрессия на эталоне: прогон по тайловой карте до/после внедрения —
  FPS не ниже; `smoke_combat.py`, `smoke_custom_map.py`, `smoke_launch.py`,
  `smoke_reliability.py` зелёные. Проверка: бенчмарк-дельты допустимы только
  вверх.
- [ ] 5.3 Приёмка цели: на эталонной машине типовая секторная карта с врагами
  и эффектами при тире «Хорошая» — средние 60 FPS без срабатывания адаптации.
  Проверка: `perf_bench` отчёт минует целевые цифры; если нет — зафиксировать
  дефект приёмки и вернуться на шаги 1-3.
- [ ] 5.4 Механики не кастрируются: прогон эквивалентности механик под всеми
  тирами — бой всеми пушками, враги всех типов + infighting, двери/
  проёмы, предметы, возрождение — логика событий (урон, состояния) идентична тиру
  «Хорошая» и мощной машине, мир не меняется от адаптации. Проверка: новый
  `smoke_mechanics_tiers.py` зелёный на эталоне: при срабатывании адаптации не
  изменяется ни одно игровое состояние, а рендер не скрывает ближних/активных
  сущностей (отсутствуют «невидимые пули»).
