## Context

См. proposal.md — Why. Лаунчеры устроены как «попробуй `py -3.12`, иначе
`py -3`, иначе `py`» и вызывают `tools/bootstrap.py run launch_client.py %*`
(`run_client.bat`) / `run_server.py` (`run_server.bat`). Строки с русским
текстом идут после `chcp 65001 >nul`.

Проверка окружения: `py -0p` показывает два интерпретатора —
`-V:3.14 *` (по умолчанию, `C:\Python314\python.exe`) и `-V:3.12`
(`...\Python312\python.exe`). Значит, падение — не в отсутствии Python, а в
разборе `.bat`.

## Goals / Non-Goals

**Goals:**
- `.bat` разбирается cmd.exe однозначно и всегда с первой попытки.
- Выбирается именно Python 3.12; аргументы `%*` доходят без искажений.
- Сообщения об ошибках читаемы, без mojibake.

**Non-Goals:**
- Не менять `tools/bootstrap.py` и `tools/launch_client.py`.
- Не переносить логику запуска с batch на иной механизм (ярлыки, exe).
- Не добавлять новую функциональность лаунчера.

## Decisions

### D1: CRLF + ASCII-only для `.bat`
Все строки заканчиваются `\r\n`, файл не содержит байтов ≥ 0x80. Русские
сообщения заменяются латинскими (`Python 3 not found. Install Python 3.12+
from https://python.org`). Это устраняет и парсинг-сбой, и mojibake — cmd
читает файл как однобайтовый, смещения совпадают.

_Альтернатива:_ оставить UTF-8, но добавить BOM и CRLF. BOM в `.bat`
ломает первую строку (`@echo off`), а UTF-8-текст в batch всё равно
хрупок; отклонена.

_Альтернатива:_ хранить `.bat` в OEM-866 (CP866). Работает, но зависит от
локали и редактора; отклонена в пользу ASCII.

### D2: Кириллица — только из Python
Если нужны русские сообщения, их печатает `tools/bootstrap.py`
(он уже использует `PYTHONUTF8=1`/`chcp`), а не `echo` в batch. Batch
остаётся ASCII.

### D3: Порядок интерпретаторов и проброс аргументов
Сохраняем кандидатов `py -3.12` → `py -3` → `py` → `python`; каждая попытка —
отдельная строка с проверкой `errorlevel`; `%*` пробрасывается везде
неизменным. При исчерпании — одно ASCII-сообщение и `pause`.

### D4: Проверка байтов как регрессионный тест
smoke-тест читает `run_client.bat`/`run_server.bat` побайтово и требует:
нет одиночных LF, есть CRLF, нет байтов ≥ 0x80, есть строки вызова
`tools\bootstrap.py` с `%*`. Это ловит регрессию кодировки навсегда.

## Risks / Trade-offs

- **[ASCII-сообщения менее дружелюбны]** Английский текст вместо русского.
  → Приемлемо: парсинг надёжнее; при желании русский текст печатает Python.
- **[Машина без 3.12]** `py -3` поднимет 3.14, где pygame может не
  установиться. → Это отдельное известное ограничение onboarding; здесь
  добавляем лишь понятное сообщение и явный порядок кандидатов.
- **[Ручное сохранение CRLF]** Редакторы могут снова записать LF. →
  Регрессионный байтовый тест (D4) и заметка в `AGENTS.md`.
