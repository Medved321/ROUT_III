## Why

Секторный рендер, введённый в `advanced-sector-editor`, использует
по-колоночную DDA-трассировку: каждая колонка экрана заново обходит линии и
портально продолжает лучи. Оригинальный DOOM 1 решил ту же задачу иначе —
BSP-деревом (NODES/SEGS/SUBSECTORS), которое даёт порядок отрисовки за O(log n)
обхода, рисует каждую стену один раз и позволяет visplane-спаны для
пола/потолка. Это и есть «родной» набор оптимизаций DOOM (colormap-свет,
клиппинг колонок, предрассчитанная геометрия), которые мы хотим перенять.
Дополнительно карты должны храниться не в JSON, а в бинарном файле с
расширением `.mt1`, устроенном как `.wad` — заголовок, каталог именованных
срезов (lumps) и сами срезы данных.

## What Changes

- **Новый бинарный формат карт `.mt1`** (в стиле Doom WAD): заголовок с магией,
  номером версии и смещением каталога; каталог именованных срезов
  (offset/size/name); срезы `VERTEXES/LINEDEFS/SIDEDEFS/SECTORS/THINGS/NAMES`
  (исходная геометрия) и вычисляемые `SEGS/SUBSECTORS/NODES/REJECT`.
  Биг-эндиан, как весь протокол проекта; версионирование, контрольная сумма,
  валидация и лимиты. Секторные карты сохраняются/передаются байтами `.mt1`;
  JSON сохраняется только для чтения старых карт (миграция) и тайловых карт
  не касается.
- **BSP-рендер секторных сцен** вместо по-колоночной DDA: обход дерева
  back-to-front, проекция seg-ов с клиппингом по колонкам (solidsegs), флаты
  через спаны (visplane), свет 16 градациями предрассчитанных текстур
  (colormap), спрайты по глубине подсекций. Сохраняются контракты
  `total-performance`: внутренний фреймбуфер + один upscale, адаптивный
  бюджет и тиры качества.
- **REJECT/BLOCKMAP ускорения**: таблица REJECT ускоряет `has_los_px`
  (проверка видимости между секторами) без изменения семантики симуляции.
- **BREAKING**: секторная карта в `CREATE_PARTY`/`JOIN_ACCEPT` передаётся
  байтами `.mt1` вместо JSON → подъём `PROTOCOL_VERSION`.

## Capabilities

### New Capabilities
- `map/sector-format`: бинарный WAD-подобный формат секторных карт `.mt1`
  (заголовок+каталог+lumps), валидация, лимиты, round-trip, миграция из JSON,
  передача байтов карты по протоколу.
- `renderer/sector-renderer`: BSP-рендер секторных сцен (обход дерева,
  клиппинг колонок, visplane-флаты, colormap-свет, спрайты по глубине)
  с сохранением бюджета кадра и тиров качества.

### Modified Capabilities
- (спеки секторных capability ещё не влиты в `openspec/specs/` — они живут
  дельтами в `advanced-sector-editor`; здесь они вводятся как новые)

## Impact

- `shared/sector_map.py`: `to_bytes/from_bytes` переходят на `.mt1`; путь
  JSON остаётся только для импорта. Новый `shared/mt1.py` (реализация
  контейнера) — сервер остаётся stdlib-only, без numpy.
- Новый построитель BSP (в `shared/` или `client/engine/bsp.py`): эвристика
  разбиения, расщепление линий, подсекции; время сборки — один раз на
  загрузку карты, кэшируется.
- `client/engine/sector_render.py`: замена `render_scene` с DDA на BSP-обход;
  интерфейс (`gs.sec_scene`, zbuffer для спрайтов) сохраняется.
- `server/`: валидация `.mt1` вместо JSON, REJECT в `has_los_px`.
- `shared/version.py` (`PROTOCOL_VERSION`), `SPEC.md`, протокольные хелперы.
- Редактор: сохранение карт в `maps/*.mt1`, импорт старых `.json`.
- Тесты: новые `smoke_mt1_*.py`, `smoke_bsp_*.py`; регрессия тайловых карт.
