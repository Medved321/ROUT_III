# Design: клиентский onboarding (новые машины)

## Context

Сегодня запуск возможен только вручную: `run_client.bat` ищет интерпретатор и при
отсутствии pygame печатает сообщение с просьбой `pip install pygame` (в сломанной
OEM-кодировке). Адрес сервера захардкожен `localhost:7777` в `run_client.py` и в
генерируемом `tools/build_client.py` (`__main__.py`); `NetworkClient.connect()`
при провале возвращает `False`, и `GameClient.run()` молча выходит. Уже
скачанный `releases/rout-client-*.pyz` не запускается ни одним скриптом.
`client.settings` уже умеет хранить конфиг в `config.json`, но только для
настроек рендера.

Проверяемые точки входа: `run_client.bat`, `run_server.bat`, `run_client.py`,
генерируемый `__main__.py` в `tools/build_client.py` (пакет `.pyz` содержит
только `client` + `shared`, НЕ `tools`).

## Goals / Non-Goals

**Goals:**
- Один bootstrap для `run_client.bat`/`run_server.bat`: venv `.venv` в корне,
  автоустановка `requirements.txt`, запуск через venv-python.
- Единая точка разрешения `(host, port, name)` из `config.json` + приоритет
  CLI-аргументов — работает одинаково в исходнике и в `.pyz`.
- Отдельный экран подключения до попадания в лобби; провал коннекта НЕ закрывает
  окно, а показывает причину (таймаут / несовместимость протокола).
- `run_client.bat` запускает установленный `.pyz`, если он новее исходников,
  иначе исходники.

**Non-Goals:**
- Автообнаружение сервера в локальной сети (DNS-SD и т.п.).
- Инсталлятор с ярлыками/автозапуском; бандлинг pygame внутрь `.pyz`.
- Изменение протокола UDP, серверного кода, схемы обновлений.
- Настройка серверного UDP-файрвола Windows на хост-машине (инструкционный
  пункт в README/чате запуска).

## Decisions

### D1. Венв-bootstrap: `tools/bootstrap.py`, .bat — тонкие обёртки
`tools/bootstrap.py` (stdlib-only, без pygame):
- `find_python()` — перебор кандидатов `[('py','-3.12'), ('py','-3'), ('py',),
  ('python',)]`, проверка `-c` рабочим интерпретатором; возвращает argv списком.
- `ensure(base_interp)` — если `.venv\Scripts\python.exe` нет → `base_interp -m
  venv .venv`; затем `venv_python -c "import pygame"`; при провале →
  `venv_python -m pip install -r requirements.txt` (пересоздание через удаление
  `.venv` + повторный `venv` в случае частичной поломки).
- `run(args)` — запускает `venv_python <args>`, возвращает код; при недоступной
  сети pip печатает внятное русское сообщение.

`.bat` становятся однострочниками в духе `py -3 tools\bootstrap.py run
run_client.py %*` (+ `chcp 65001` и `PYTHONUTF8=1` для корректной кодировки).
Альтернатива (логика в .bat) отвергнута: в batch нет проверки импорта pygame и
переносимости версий, а Python-модуль тестируется smoke-тестом как функция.

### D2. Адрес в конфиге: ключи `server_host`/`server_port`/`player_name` в `client.settings`
Расширяем `Settings.DEFAULTS` тремя ключами (`"localhost"`, `7777`, `"Player"`).
`Settings.load/save` уже фильтруют по `DEFAULTS`, поэтому новые ключи
автоматически читаются/пишутся в `config.json`. Новая функция-геттер
`launch_config(cli_overrides)` в `client/settings.py` (пакет `client` входит в
`.pyz`): читает значения, затем применяет `--host/--port/--name` из argv. В
настройки-UI не добавляем (поля рендера из `SPEC` остаются прежними). Альтернативу
(модуль в `tools/`) отвергли: `tools` не бандлится в пакетный артефакт.

### D3. Экран подключения `client/connect_screen.py` + рефактор потока `GameClient`
Новый экран: поля хост/порт/имя (предзаполнены из конфига), кнопка
«Подключиться», строка статуса/ошибки. `GameClient.run()` перестраивается:
пока не подключены — цикл экрана подключения; после успеха — прежняя
диспетчеризация (лобби/game). Попытка коннекта `await network.connect(name)`
выполняется внутри кадра экрана с состоянием «Подключение…». На провале:
- таймаут рукопожатия (>5с, `connect()` вернул `False` без `last_error` о
  версии) → «Сервер недоступен».
- `last_error` с несовместимостью протокола (`Несовместимая версия…`) → та же
  строка на экране.
Затем экран остаётся открытым, поля редактируемы, повторная попытка без
перезапуска. Для повтора `GameClient` создаёт свежий `NetworkClient` из текущих
значений полей (старый транспорт закрыт) и при успехе подменяет `self.network`.
`loc_kick` не меняется: существующие ошибки лобби (`last_error`) продолжают
работать как раньше.

### D4. Лаунчер артефакта: `tools/launch_client.py`
`launch_client.py` (stdlib + `shared.releases`):
- `latest installed` = `releases.latest_version(default_releases_dir())`;
- сравнение с `shared.version.CLIENT_VERSION` по кортежам компонентов
  (`1.0.9` < `1.0.10`);
- если `latest > CLI_VERSION` → `subprocess` `venv_python <pyz> <argv…>`
  (pyz сам прочитает адрес из конфига, см. D2), иначе → `run_client.py <argv…>`.
`run_client.bat` вызывает `bootstrap run launch_client.py %*`; `run_server.bat` —
`bootstrap run run_server.py %*`.

### D5. Генерируемый `__main__.py` (build_client) читает конфиг
`MAIN_TEMPLATE` в `tools/build_client.py` заменяет ручной разбор `--host/--port/
--name` на вызов `client.settings.launch_config(sys.argv)`. Тем самым артефакт и
исходник используют один источник (Requirement «Адрес сервера»).

## Risks / Trade-offs

- **pip требует сеть при первом запуске** → точное русское сообщение + код
  возврата; повторный запуск после появления сети доустанавливает.
- **Время создания venv на новой машине** (десятки секунд) → сообщение
  «Установка зависимостей…» перед шагом; venv создаётся один раз.
- **`py` лаунчер отсутствует** (только `python.exe`) → фолбэк-кандидат
  `('python',)` в D1.
- **Сравнение версий артефакта** не-числовых компонентов (например
  `1.0.0-beta`) → сравнение по кортежам с числовым fallback; неверный формат
  трактуется как «запустить исходники» (консервативно).
- **Старые машины с уже настроенным pygame в глобальном окружении** получат
  отдельный `.venv` → единообразие, без влияния на системный Python.
- **Окно-файрвол UDP на хост-машине** → вне зоны кода; строкой-подсказкой в
  выводе сервера.

## Migration Plan

Безмиграционный: новые ключи конфига имеют дефолты; venv создаётся/чинится при
первом запуске через новые .bat. Откат — вернуть прежние `.bat`/`run_client.py`;
`.pyz` каталог и updater-механизм не меняются.

## Open Questions

- Нужен ли ввод адреса также в Settings-экране лобби? Решение: нет — адрес
  вводится только на экране подключения до коннекта (в лобби менять сервер
  нельзя без переподключения). Если понадобится — отдельное изменение.
