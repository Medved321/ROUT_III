## Purpose

Обеспечивает уверенный первый запуск клиента на новой машине: зависимости
устанавливаются автоматически, адрес сервера конфигурируется и переживает
перезапуски, ошибки подключения объясняются пользователю, а свежеполученный
артефакт клиента запускается без ручных команд.

## ADDED Requirements

### Requirement: Автоустановка зависимостей при запуске

Launch-скрипт клиента SHALL перед запуском создать или восстановить
изолированную среду (venv) в корне проекта и установить в неё зависимости из
`requirements.txt`. Игра MUST запускаться через python именно этой среды; если
необходимая зависимость (pygame) в среде не импортируется, среда SHALL
пересоздаваться и устанавливаться заново автоматически. На машине достаточно
лишь установленного Python — никаких ручных шагов по установке библиотек.

#### Scenario: Свежая машина без зависимостей

- **WHEN** запускают `run_client.bat` на машине, где нет ни venv, ни pygame
- **THEN** скрипт создаёт venv, устанавливает зависимости и запускает клиент без ручных действий пользователя

#### Scenario: Сломанная или пустая среда

- **WHEN** в существующем venv не импортируется pygame
- **THEN** среда пересоздаётся, зависимости устанавливаются заново и клиент запускается

#### Scenario: Сервер на новой машине

- **WHEN** на новой машине запускают `run_server.bat`
- **THEN** сервер стартует через ту же изолированную среду с установленными зависимостями

### Requirement: Адрес сервера и имя игрока в конфиге

Клиент SHALL читать адрес сервера (`host`, `port`) и имя игрока из `config.json`.
При отсутствии этих ключей используются значения по умолчанию: `localhost`,
`7777`, `Player`. Все точки входа клиента — исходник, установленный артефакт
`.pyz` и лаунчер — MUST использовать единый источник адреса (тот же конфиг).
Параметры запуска `--host`/`--port`/`--name` SHALL иметь приоритет над конфигом
только для текущего запуска.

#### Scenario: Сохранённый адрес применяется

- **WHEN** в `config.json` сохранены `server_host`/`server_port`
- **THEN** при следующем запуске клиент подключается к этому адресу без параметров командной строки

#### Scenario: Дефолт при отсутствии ключей

- **WHEN** в `config.json` нет ключей сервера
- **THEN** клиент подключается к `localhost:7777` с именем `Player`

#### Scenario: Приоритет параметров запуска

- **WHEN** клиент запущен с `--host` и/или `--port`
- **THEN** для этого запуска используется указанный адрес, а сохранённый в конфиге не изменяется

### Requirement: Экран подключения

Клиент MUST перед подключением показывать экран с полями «хост», «порт»,
«имя» и кнопкой подключения, предзаполненными из конфига. При неуспешном
подключении клиент MUST оставаться открытым и показывать на этом экране
понятное сообщение: таймаут рукопожатия («Сервер недоступен»), несовместимость
версии протокола (с указанием версий сервера и клиента). После исправления
адреса пользователь SHALL иметь возможность повторить подключение без
перезапуска программы.

#### Scenario: Успешное подключение

- **WHEN** пользователь вводит адрес и нажимает кнопку подключения, и рукопожатие успешно
- **THEN** клиент переходит в лобби (меню партий)

#### Scenario: Сервер недоступен

- **WHEN** адрес не отвечает на рукопожатие (таймаут)
- **THEN** на экране отображается сообщение о недоступности сервера и клиент остаётся открытым

#### Scenario: Несовместимость версии протокола

- **WHEN** сервер и клиент имеют разные версии протокола
- **THEN** на экране отображаются версии сервера и клиента с подсказкой обновить клиент, и клиент остаётся открытым

### Requirement: Запуск установленного артефакта

Лаунчер клиента SHALL запускать последний установленный артефакт
`releases/rout-client-*.pyz`, если его версия новее встроенной в исходниках
версии клиента; иначе лаунчер SHALL запускать исходники из репозитория.
Запущенный артефакт MUST использовать адрес сервера и имя игрока из конфига
(тот же единый источник, что и исходник), а не встроенный дефолт.

#### Scenario: Установленный артефакт новее исходников

- **WHEN** в `releases/` установлен `.pyz`, версия которого новее версии исходников
- **THEN** `run_client.bat` запускает этот `.pyz`, а не исходники

#### Scenario: Исходники актуальнее установленного артефакта

- **WHEN** установленный `.pyz` отсутствует или не новее версии исходников
- **THEN** `run_client.bat` запускает клиент из исходников

#### Scenario: Артефакт использует конфиг адреса

- **WHEN** запущен `.pyz` с сохранённым в `config.json` адресом сервера
- **THEN** он подключается к этому адресу, а не к встроенному `localhost:7777`
