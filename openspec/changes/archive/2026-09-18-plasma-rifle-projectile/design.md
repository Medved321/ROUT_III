## Context

См. proposal.md — Why. Сервер уже шагает авторитетные снаряды врагов
`server/game_world.py:_update_bullets` и `_fire_enemy_proj`, рассылает их в
`WORLD_STATE` (`shared/protocol.py` bullets `!ffBBB`), клиент через
`bridge.py` кладёт их в `gs.bul`. Рендер уже умеет рисовать светящийся
проджектайл игрока: ветка `s_obj.get('from_player')` в `rendering.py`
(3 круга, без `rotozoom`), просто мост её не заполняет. Хитскан-оружия
считаются в `server/weapons.py:handle_shoot` (пеллеты/конус/стены), но точку
попадания на клиент не возвращают.

## Goals / Non-Goals

**Goals:**
- Серверный шар для RIFLE (урон по долёту), видимый всем клиентам.
- Следы от выстрелов по честным impact-событиям от сервера.
- Бюджет перформанса: без per-frame `rotozoom`/аллокаций на шар/частицу,
  лимиты активных сущностей, дешёвые примитивы.

**Non-Goals:**
- Новый отдельный слот оружия PLASMA (плазма = RIFLE).
- Изменение сети/рендера для кастомных `proj_sprite`-пушек ROUT_II_III.
- Вражеские AI-пушки (их шары уже есть и не меняются).
- Текстуры/модели/звуки внут. визуал — только свечение/частицы.

## Decisions

### D1: Плазма-шар — серверный, по долёту (подход B)
RIFLE в `handle_shoot` спавнит шар в `world.bullets` с `from_player`/`src`,
а не решает урон мгновенно. Шар шагается в `_update_bullets` (общий цикл),
урон — по попаданию (враг или игрок PvP), как у вражеских пуль —
переиспользуется «буквально» существующая проверка `is_wall_px`/`players`.

_Альтернативы:_ косметический шар на клиенте (урон уходит мгновенно — расходится
с видимым полётом, отброшено); мгновенный сетевой «шар-маркер» без симуляции.

### D2: Данные в WORLD_STATE — флаг `from_player` в пулях
Расширить bullets с `!ffBBB` до `!ffBBBB` (xf/fff r,g,b + flag), флаг = `from_player`.
Клиент видит one-byte флаг и кладёт шар в путь рендера «orb игрока». Пакет стабилен
по формату (не фрагментирован, big-endian), update — backward-compatible по
длине (flag по умолчанию 0 → у старых клиентов пули рисовались бы серым/жёлтым).

_Альтернатива:_ отдельный список `player_bullets` в WORLD_STATE — больше байт и
два пути рендера; отброшено ради простоты.

### D3: Impact-события — новый короткоживущий список в снапшоте
`handle_shoot` для хитскан-пушек при попадании в стену/врага пишет в
`world.impacts` запись `{x, y, type}` (тип: `wall`/`enemy`), TTL ~ 10–15 тиков,
лимит (например, 64). Снапшот едет блоком `!H count` + `!ffB` (x,y,type). Клиент
по событию вызывает `spawn_sparks`/`spawn_smoke_trail`/`spawn_particles` в этой
точке.

_Альтернативы:_ локальная прикидка клиента (след в нечестном месте — отброшено);
отдельный unreliable-канал по типу BULLET_SPAWN (лишняя механика — отброшено).

### D4: Бюджет перформанса
- Лимит активных шаров игрока на мир (напр. `MAX_PLAYER_PROJ = 32`), TTL по
  `max_dist`.
- Impact-лист капается (напр. 64) и чистится по TTL.
- Клиент рисует шар `from_player` кругами (уже в рендере); частицы уже
  капаются `MAX_PARTICLES`. Никаких `pygame.transform.rotozoom` на кадр.

## Risks / Trade-offs

- **[Wire-формат ломается]** bullets `!ffBBB` → `!ffBBBB` → очистить старый
  формат/версию. → PROTOCOL_VERSION уже есть; боди-код читается по длине,
  старая версия клиента и сервер одинаковой версии — безопасно.
- **[RIFLE стал не мгновенным]** может показаться медленнее на близкой дистанции.
  → Скорость шара подобрать из ROUT_II_III (`proj_speed` ~12 px/frame → конверт
  через `fps60_per_tick`), тонкая настройка в tasks.
- **[Impact-события без hit-инфо]** хитскан без попадания (промах в пустоту)
  не даёт след. → Приемлемо: след только при попадании; для промаха можно
  локальную вспышку у дула.
- **[Падение FPS от частиц]** много impact→много частиц. → `spawn_*` уже
  упираются в `MAX_PARTICLES`, лимит impact-событий + TTL.

## Migration Plan

1. Сначала протокол (`shared/protocol.py` + SPEC.md) — новые поля в bullets и
   impacts, `PROTOCOL_VERSION` +1.
2. Затем сервер: симуляция шара, damage, impact-события, снапшот.
3. Затем клиент: bridge (bullets с flag, impacts), рендер orb (проверить
   ветку `from_player`), частицы из impact.
4. Тесты/регрессия: `smoke_*` (протокол, сервер, headless-рендер), `py_compile`.
   Откат — по PROTOCOL_VERSION (старый клиент с новым сервером не проходит).
