## Purpose

Гарантирует запуск игры на Linux/Unix-подобных системах, где `.bat`-лаунчеры
неприменимы: shell-скрипты находят подходящий CPython или автоматически готовят
его в пользовательском каталоге без прав root, после чего запускают игру через
общий `tools/bootstrap.py` с той же схемой venv и зависимостей, что и на Windows.

## ADDED Requirements

### Requirement: Исполняемые POSIX-лаунчеры

В корне проекта SHALL существовать `run_client.sh` и `run_server.sh`: текстовые
файлы с shebang, совместимым с `/bin/sh`, переводами строк LF и выставленным
исполняемым битом. Лаунчер SHALL работать при запуске из любого текущего
каталога, `run_client.sh` SHALL запускать цель `tools/launch_client.py`, а
`run_server.sh` — `run_server.py`. Все аргументы командной строки SHALL
передаваться цели без потери и искажения.

#### Scenario: Запуск из другого каталога

- **WHEN** пользователь вызывает `/path/to/ROUT III/run_server.sh --port 9000`
  из произвольного каталога
- **THEN** лаунчер находит корень проекта относительно самого скрипта и
  запускает сервер, не завися от текущего каталога

#### Scenario: Аргументы доходят целиком

- **WHEN** пользователь запускает `run_client.sh --name Test --host 10.0.0.1`
- **THEN** `--name Test --host 10.0.0.1` доходят до запускаемой цели без
  изменения

#### Scenario: Формат файлов лаунчера

- **WHEN** `run_client.sh` или `run_server.sh` прочитан побайтово
- **THEN** он начинается с shebang, не содержит пар CRLF и зарегистрирован как
  исполняемый файл в git

### Requirement: Поиск подходящего интерпретатора

Лаунчер SHALL использовать CPython версии не ниже 3.12 обычной сборки
(free-threaded сборки SHALL быть отклонены). Кандидаты проверяются в порядке
`python3.12`, затем `python3`, затем `python`. Неподходящий кандидат (слишком
старый или free-threaded) SHALL NOT запускать игру; лаунчер переходит к
следующему кандидату, а при их исчерпании — к автоподготовке интерпретатора.
Каталог уже подготовленного интерпретатора SHALL задаваться переменной
окружения `ROUT_PYTHON_DIR` и проверяться первым.

#### Scenario: Есть python3.12

- **WHEN** в системе есть `python3.12`, а также более старый `python3`
- **THEN** лаунчер выбирает `python3.12` и запускает игру через него

#### Scenario: Слишком старый интерпретатор

- **WHEN** единственный доступный Python — 3.10
- **THEN** он не используется для запуска, и лаунчер переходит к автоподготовке
  интерпретатора 3.12

#### Scenario: Free-threaded сборка

- **WHEN** кандидат — free-threaded CPython (без GIL)
- **THEN** он отклоняется, и выбирается следующий подходящий кандидат

### Requirement: Автоподготовка CPython 3.12 в пользовательский каталог

Когда подходящий интерпретатор не найден, лаунчер SHALL скачать pinned
standalone-сборку CPython 3.12 `install_only` для архитектуры машины
(`x86_64` или `aarch64`, gnu), проверить её `sha256` и распаковать в
пользовательский каталог без прав root. Уже подготовленный интерпретатор SHALL
переиспользоваться при следующих запусках без повторной загрузки. При
неизвестной архитектуре или недоступности загрузки установка SHALL
завершиться понятной ошибкой и ненулевым кодом без запуска игры.

#### Scenario: Подходящего Python нет

- **WHEN** на машине нет CPython ≥ 3.12 и `ROUT_PYTHON_DIR` не задан
- **THEN** лаунчер скачивает standalone CPython 3.12 для архитектуры машины,
  проверяет `sha256`, распаковывает в пользовательский каталог и запускает игру
  этим интерпретатором

#### Scenario: Повторный запуск

- **WHEN** standalone-интерпретатор уже подготовлен предыдущим запуском
- **THEN** повторная загрузка не выполняется, используется существующий
  интерпретатор

#### Scenario: Неизвестная архитектура

- **WHEN** `uname -m` возвращает архитектуру без pinned-сборки (например,
  `riscv64`)
- **THEN** выводится понятное сообщение о неподдерживаемой архитектуре, и игра
  не запускается

#### Scenario: Автоподготовка запрещена

- **WHEN** задано `ROUT_PYTHON_NO_INSTALL=1` и подходящего интерпретатора нет
- **THEN** лаунчер не выполняет загрузку, печатает подсказку установить
  Python 3.12 и завершается с ненулевым кодом

### Requirement: Целостность загружаемой сборки

Перед распаковкой лаунчер SHALL вычислить `sha256` загруженного архива и
сравнить с зафиксированным ожидаемым значением. При несовпадении распаковка и
запуск игры SHALL NOT выполняться; частично загруженный/распакованный артефакт
SHALL удаляться, а пользователю SHALL выводиться ошибка.

#### Scenario: Несовпадение sha256

- **WHEN** контрольная сумма загруженного архива отличается от ожидаемой
- **THEN** установка прерывается, временные файлы удаляются, игра не
  запускается, код выхода ненулевой

### Requirement: Читаемые сообщения об ошибке

Все сообщения об ошибках лаунчера SHALL выводиться в stderr и SHALL быть
понятными человеку (без mojibake), включая случаи отсутствия загрузчика
(`curl`/`wget`), отсутствия сети и невозможности распаковки.

#### Scenario: Нет ни curl, ни wget

- **WHEN** подходящего Python нет, а в системе отсутствуют и `curl`, и `wget`
- **THEN** выводится сообщение с подсказкой установить загрузчик или Python
  3.12 вручную, и игра не запускается

#### Scenario: Нет сети

- **WHEN** загрузка не удаётся из-за отсутствия сети
- **THEN** выводится понятное сообщение об ошибке загрузки, временные файлы
  удаляются, код выхода ненулевой

### Requirement: Единая настройка зависимостей через bootstrap

Получив подходящий интерпретатор, лаунчер SHALL запускать игру через
`tools/bootstrap.py run <цель>`, чтобы venv и зависимости из `requirements.txt`
настраивались так же, как на Windows. `tools/bootstrap.py` SHALL рассматривать
интерпретатор, которым он запущен (`sys.executable`), как первого кандидата,
когда тот удовлетворяет требованиям, — чтобы запуск на Linux через `python3`
(когда имя `python` отсутствует) не завершался ошибкой «подходящий Python не
найден».

#### Scenario: Зависимости ставятся автоматически

- **WHEN** лаунчер запускает игру на машине без venv и без pygame
- **THEN** `tools/bootstrap.py` создаёт `.venv`, устанавливает зависимости и
  запускает клиент/сервер без ручных действий

#### Scenario: bootstrap через python3 на Linux

- **WHEN** `tools/bootstrap.py` запущен интерпретатором с именем `python3`, а
  команды `py` и `python` в системе отсутствуют
- **THEN** bootstrap использует этот же интерпретатор и не завершается ошибкой
  поиска Python
