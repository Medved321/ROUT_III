# Design

## Context

См. `proposal.md` для мотивации. Текущее состояние, которое определяет решение:

- Миникарта рисуется внутри `engine/rendering.py` и работает только при
  `gs.M_SZ > 0`; `RenderBridge.set_sector_map()` обнуляет `gs.MAP`/`gs.M_SZ`,
  поэтому секторные партии её лишены.
- Тайловый и секторный редакторы — независимые модули. Вход в лобби, `_editor_kind`
  и обе кнопки переключения живут в `client/client.py`, `client/lobby_screen.py`,
  `client/editor_screen.py`, `client/sector_editor_screen.py`.
- Декоративные глифы встречаются только в пользовательских строках интерфейса
  (`▶`, `✓`, `▾`, `▲/▼`, стрелки, `▌`, `█`); кириллица, `—`, `…`, `×`, `°` —
  обычная типографика и не трогаются.
- Частота тиков продублирована в `shared/combat.py` и `server/game_data.py`,
  а часть клиентского кода (врата стрельбы, время матча) использует литерал `20`.
  Протокол версии 15 не несёт частоту.

Ограничения: сервер и `shared/` остаются stdlib-only; `engine/` не импортирует
`client.*`, `server.*` и сетевые модули `shared.*`; полный набор механик должен
работать при любой частоте тиков.

## Goals / Non-Goals

**Goals:**

- Дать секторному режиму миникарту геометрии без сущностей и без аллокаций на кадр.
- Оставить единственный editor UI — секторный — не убивая совместимость с тайловыми картами.
- Сделать интерфейс чисто текстовым в части декоративных символов.
- Сделать `--fps` единственным источником частоты тиков и передать её клиенту.

**Non-Goals:**

- Не менять форматы карт, ECS, логику урона, AI, дэша и подбора предметов.
- Не добавлять тумблер «показывать сущности» для секторной миникарты.
- Не удалять тайловые карты из рантайма, сети и тестов.
- Не добавлять серверный `config.json`: частота задаётся только аргументом запуска.
- Не менять `PLAYER_INPUT`, `FIRE`, `WORLD_STATE` и игру на 20 тиках по умолчанию.

## Decisions

### 1. Миникарта секторов — отдельный модуль движка

Добавить `engine/sector_minimap.py`, который получает активную сцену из
`gs.sec_scene`, строит набор отрезков по `linedefs` сцены и рисует их в уже
существующий прямоугольник миникарты. Модуль импортирует только pygame,
`engine.viewport`, `engine.game_state` и `shared.sector_map`, поэтому не нарушает
границу движка. `engine/rendering.py` зовёт его лениво из ветки `else` после
проверки `gs.show_minimap`; при отсутствии сцены ветка ничего не рисует.

Геометрия: сплошные линии рисуются ярче, двусторонние проёмы — тусклее, границы
парящих плит — отдельным оттенком. Никаких маркеров сущностей, никакого
fog-of-war: в секторном режиме миникарта показывает всю геометрию текущей карты.
Масштаб и отступ берутся из `ui_px`, поэтому доля окна сохраняется от 640×480 до
4K. Набор отрезков кэшируется по `(id(scene), (width, height))`; в устоявшемся
окне кадр не пересобирает список и не создаёт `Surface`.

Альтернативы: рисовать секторную миникарту прямо в `rendering.py` (отвергнуто —
там уже перегруженный кадровый путь и легко потерять кэш), или переиспользовать
тайловую сетку через `SectorMap.from_tiles` (отвергнуто — теряется геометрия
секторов и плит).

### 2. Удаление редактора — только UI

Удаляется `client/editor_screen.py`, импорт/инстанс `MapEditorScreen`, поле
`_editor_kind`, ветки `tile`/`sector` и тайловая ветка `play` в
`client/client.py` и кнопка «Тайлы» в редакторе секторов. Кнопка и клавиша `E`
в лобби остаются, но ведут только в секторный редактор (как требуют сценарии
`client/map-editors`). `LobbyScreen` сохраняет ту же сетку кнопок; метка входа
уточняется до «Секторный редактор [E]», а хитбокс по-прежнему берётся из
`layout_row()` по фактической ширине текста.

`client/map_editor.py` сохраняет `CHAR_TO_TILE`, `TILE_CHAR_TO_TEX`,
`ENEMY_NAMES`, `ITEM_NAMES`: они нужны `bridge.py`, редактору секторов и тестам.
Класс `TileEditor` и его палитра удаляются как мёртвый код после исчезновения
`editor_screen.py`. `shared.map_data.GameMap`, DDA-рендер, загрузка `.json`,
`SectorMap.from_tiles` и `assets/maps/default.json` остаются.

Альтернатива — оставить переключатель, но спрятать его: отвергнута, потому что
оставляет второй путь в код, который пользователь всё равно может найти.

### 3. Текст вместо пиктограмм

Правятся только пользовательские строки. Замены: «▶ Играть» → «Играть (F5)»,
«Сетка ✓» → «Сетка: вкл/выкл», «Карты ▾» → «Список карт», «пол ▲/▼» →
«пол выше/ниже», подсказки со стрелками → «влево/вправо/вверх/вниз», текстовый
курсор `▌` → обычный ASCII-символ, служебная строка с `█` → текст без блока.
Новый smoke-тест сканирует строковые литералы UI-модулей на запрещённые
кодовые точки; кириллица и типографская пунктуация в whitelist.

Альтернатива — заменить глифы изображениями: отвергнута, потому что добавляет
ресурсы и не решает проблему читаемости подписей.

### 4. Один источник частоты тиков

`shared/combat.py` объявляет `DEFAULT_TICK_RATE = 20`, диапазон 5–120,
`validate_tick_rate()`, `tick_interval(rate)`, `fps60_per_tick(rate)` и
принимает `tick_rate` в `wpn_cooldown_ticks()`. `server/game_data.py` реэкспортирует
старые имена `TICK_RATE`/`TICK_INTERVAL` как значения по умолчанию для совместимости
импортов, но рантайм использует только значение, хранимое в `GameServer`.

`GameServer.__init__(..., tick_rate=DEFAULT_TICK_RATE)` проверяет диапазон,
сохраняет `self.tick_rate`/`self.tick_interval` и передаёт их в `Lobby`, `GameWorld`
и `handle_shoot` при создании партий. Из модульных констант выводятся только
значения по умолчанию; все длительности, скорости и переводы миллисекунд в тики
становятся функциями от `tick_rate`. В `_game_loop()` дедлайны, `TICK_DRAIN_MAX`
и сон до следующего дедлайна работают от `self.tick_interval`.

`server/cli.py` содержит единственный парсер `parse_server_args(argv)`,
возвращающий `host`, `port`, `tick_rate`; `run_server.py` и `server/__main__.py`
вызывают его. Ошибка значения печатается в stderr и завершает процесс до открытия
сокета. `.bat`/`.sh` уже передают аргументы дальше, правка не требуется.

### 5. Протокол и клиентская синхронизация

`encode_hello_ack()` дописывает `tick_rate` как `uint8` **в конец** существующего
payload, чтобы не сдвигать смещения полей обновления; `decode_hello_ack()`
возвращает его с дефолтом 20 для старых тестовых данных. `PROTOCOL_VERSION`
повышается с 15 до 16, поэтому старый клиент отвергается по уже существующей
проверке версии. Форматы `PLAYER_INPUT`, `FIRE`, `WORLD_STATE` не меняются.

`NetworkClient` сохраняет полученную частоту в `hello_ack`. `GameClient` берёт её
оттуда с дефолтом 20 для одиночных smoke-тестов и использует в:
- вратах стрельбы и длительности предсказанной отдачи;
- задержке интерполяции `INTERP_DELAY`;
- переводе номера тика матча в секунды для HUD/экрана окончания.

Альтернатива — не передавать частоту и оставить клиент на 20: отвергнута, потому
что при `--fps 30` клиент обрывал бы отдачу и показывал неверное время матча.

### 6. Проверки

Новые `smoke_sector_minimap.py` и `smoke_server_fps.py` проверяют:
геометрию и отсутствие сущностей на секторной миникарте, кэш на устоявшемся
кадре, `--fps`/диапазон/парсер, `HELLO_ACK` round-trip, удержание частоты на
искусственных часах и отсутствие подряд идущих нулевых снов. Существующие
`smoke_fire_intent.py`, `smoke_hitscan.py`, `smoke_weapon_anim.py` параметризуются
частотой. `smoke_ui.py`, `smoke_menu_layout.py`, `smoke_custom_map.py` обновляются
под один редактор и текстовые подписи. `tools/check_engine_imports.py` получает
новый модуль в списке разрешённых.

## Risks / Trade-offs

- [Риск] Частота 120 Гц усиливает джиттер client-side интерполяции →
  Митигация: диапазон ограничен 120, `INTERP_DELAY` выводится из частоты, а не
  хардкодится; тест на искусственных часах держит устойчивость цикла.
- [Риск] Старый клиент не понимает новое поле HELLO_ACK →
  Митигация: поле дописано в конец, версия протокола повышена, несовместимость
  обрабатывается до разбора игровых пакетов.
- [Риск] Удаление `TileEditor` сломает импорты тестов →
  Митигация: константы остаются на месте; проверяется grep-ом по `client.*` и
  прогоном всех smoke-тестов.
- [Риск] Миникарта начнёт рисовать слишком много линий на большой карте →
  Митигация: кэш отрезков и отсутствие поверхностей на кадр; лимиты карты уже
  ограничены `MAX_LINEDEFS`.
- [Риск] Замена глифов изменит ширину кнопок и сломает hit-тест →
  Митигация: все кнопки уже меряются по фактической ширине метки; smoke menu
  layout проверяет совпадение нарисованного и кликабельного.

## Migration Plan

1. Внести спец-дельты и прогнать `openspec validate --strict`.
2. Сначала добавить миникарту и её тест: это изолированное изменение движка.
3. Затем убрать редакторский UI и глифы, обновив menu/UI smoke-тесты.
4. После этого ввести частоту тиков: общий default → сервер → протокол → клиент → тесты.
5. Обновить `SPEC.md`, `AGENTS.md` и `openspec/specs/001-doom-shooter.md` (строки про
   тик 20 Гц и состав меню).
6. Откат по шагам: отключить миникарту флагом, вернуть UI-строки из git, вернуть
   `PROTOCOL_VERSION = 15` и убрать поле HELLO_ACK вместе с клиентской сверкой —
   только все три правки вместе, иначе стороны разойдутся при разборе.

## Open Questions

Нет. Все существенные вопросы (объём удаления редактора, содержимое миникарты, способ
задачи частоты и список глифов) уточнены пользователем до создания change'а.
