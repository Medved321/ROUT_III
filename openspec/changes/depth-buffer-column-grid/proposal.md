# Proposal

## Why

Клиент падает с `IndexError: list index out of range` в
`engine/rendering.py:1088` — на строке проверки глубины спрайта:

```python
idx = max(0, min(const.W // SCALE - 1, sx // SCALE))
if 0 <= sx < const.W and z_b[idx] > occ:
```

Это не «редкий уголок», а закономерный итог того, что у колоночной сетки
глубин **два независимых источника истины**.

`render()` вычисляет номер колонки из `const.W` и `rendering.SCALE` — то есть
предполагает, что `z_b` содержит ровно `const.W // SCALE` элементов. Для
тайлового пути это верно. Для секторного пути — нет: буфер строит
`sector_render.render_scene()` как `iw = W // gs.render_scale`, где
`gs.render_scale` живёт в `game_state`, а не в `constants`.

Отсюда две независимые поломки, и обе уже в проде:

**1. Расхождение шага — это сам крэш.** Как только `gs.render_scale` больше
`const.SCALE`, буфер короче, чем `const.W // SCALE`, и верхняя граница самого
clamp'а оказывается за концом буфера. Это не экзотика: `render_scale` —
настройка из `config.json` плюс ступень адаптивного контроллера качества
(`client/performance.py`, ладдер доходит до `MAX_ADAPTIVE_SCALE = 8`), а
`const.SCALE` по умолчанию 4. Воспроизведено прогоном по сетке
`const.W × SCALE × gs.render_scale` на настоящем `render()` с секторной
картой: `IndexError` в `rendering.py:1088` возникает ровно при
`gs.render_scale > const.SCALE` и не зависит от размера окна.

**2. Расхождение ширины — тихая порча картинки.** `engine/sector_render.py:25`
делает `from engine.constants import W, H, TILE, TEX_W, FOV, CAM_Z` — это
**копии на момент импорта**. А `client/renderer.py:96` переписывает
`const.W`/`const.H` при каждом ресайзе окна, а `client/settings.py:367` —
`const.FOV`. То есть после первого же ресайза секторный рендер kompozит картинку
для ширины окна на старте, `project_object()` проецирует `sx` для той же
старой ширины, а экран — для текущей. Падения тут нет: `idx` зажимается, и
спрайты просто отсекаются/рисуются не по той колонке. Выглядит как «секторная
карта едет при ресайзе». Изменение FOV в настройках ломает секторный рендер
по той же причине, а в проекции вообще не участвует.

**3. Тот же дефект в двух других местах.** `draw_particles()`
(`engine/particles.py:242`) делит на `gs.render_scale`, тогда как буфер в
тайловом режиме построен по `const.SCALE` — частицы отсекаются не по той
колонке. Туман (`engine/rendering.py:1459`) рисует полосу шириной `SCALE` на
каждую колонку, то есть тоже считает, что шаг буфера равен `SCALE`, — в
секторном режиме дымка съезжает и последние колонки уезжают за край.

Все три места лечатся одним и тем же: **буфер сам знает свою сетку**, и
единственное, что нужно снаружи, — это спросить у него номер колонки.

## What Changes

- **Единый источник истины для сетки глубин.** Появляется `depth_col(z_b, sx,
  screen_w)`: возвращает номер колонки буфера, в которую попадает экранный
  столбец `sx`, либо `-1`, если такой колонки нет. Номер выводится из
  `len(z_b)` — из самого буфера, а не из `SCALE`/`gs.render_scale`/`const.W`.
  `len(z_b)` — это ровно то, чем буфер является, поэтому функция не может
  выйти за границу по построению.
- **Все пять мест обращения к буферу глубин переводятся на неё**: четыре
  проверки окклюзии спрайтов/предметов/ботов/игроков в `engine/rendering.py`
  и `draw_particles()` в `engine/particles.py`. «Нет колонки» (`-1`) трактуется
  как «не видно», а не зажимается на соседнюю: зажим молча тестирует глубину
  чужой колонки, и спрайт либо пропадает, либо проявляется сквозь стену.
- **Лишний параметр `NC` убирается** из `draw_particles()`. Он был вторым
  источником истины, который молча игнорировался бы дальше; `smoke_perf.py`
  обновляется под новую сигнатуру. Дефолт `vh=const.H` заодно читается в
  момент вызова, а не замораживается импортом.
- **Геометрия колонки тумана** выводится из той же сетки через уже
  существующий `_frame_column_span(i, nc, iw)`, а не через `i * SCALE`.
- **`sector_render` перестаёт замораживать размеры и FOV на импорте.** `W`,
  `H`, `FOV` читаются живьём из `const`; по значению остаются только
  `TILE`/`TEX_W`/`CAM_Z`, которые никто не переприсваивает. Буфер, проекция
  `sx` и экран после этого согласованы по определению — ресайз окна и смена FOV
  в настройках больше не расходятся.
- **`NC` переезжает внутрь тайловой ветки** `render()`: после правки это
  исключительно тайловая величина.

**Non-goals** (осознанно не в этом change):

- **Смена сетки z-буфера.** Тайловый путь по-прежнему строит буфер по
  `const.SCALE`; менять число лучей на кадр нельзя — это ломает
  `total-performance` и бюджет кадра.
- **Склейка двух путей.** Секторный рендер по-прежнему отдаёт свой буфер из
  `sector_render`; change не переписывает рендер, он чинит контракт между ним и
  потребителями.
- **Протокол, сервер, ассеты.** Не затрагиваются.
- **Удаление мёртвого `_render_sector_scene_legacy()`.** Он помечен как
  удалённый ещё в `advanced-sector-editor` и в этом проходе не вызывается;
  отдельная задача на чистку.

## Capabilities

### New Capabilities

- `renderer/depth-buffer`: колоночная сетка глубин как контракт. Буфер сам
  определяет свою сетку, потребители спрашивают его, а не пересчитывают
  (`IndexError` в `rendering.py:1088` — прямое следствие нарушения этого
  контракта).

> Capability введена этим change: требований о z-буфере и его контракте с
> потребителями в `openspec/specs/` пока нет, поэтому дельта объявлена как
> **Added**. Существующие требования к внутреннему разрешению
> (`bsp-renderer-mt1-format` → `renderer/sector-renderer`,
> «Внутренний буфер и бюджет кадра») change не нарушает и не меняет: он
> уточняет, откуда берётся число колонок, оставляя само число прежним.

### Modified Capabilities

- Нет. `renderer/sector-renderer` и `total-performance` не меняются: число
  колонок, разрешение внутреннего буфера и бюджет кадра остаются как были.

## Impact

- **Рендер**: `engine/rendering.py` — четыре окклюзии спрайтов переводятся на
  `depth_col`, геометрия полосы тумана — на `_frame_column_span`, `NC`
  переезжает в тайловую ветку; `engine/framebuffer.py` — новый `depth_col()`.
- **Эффекты**: `engine/particles.py` — `draw_particles()` без параметра `NC`,
  окклюзия по `depth_col`, дефолт `vh` читается в момент вызова.
- **Секторный рендер**: `engine/sector_render.py` — `W`/`H`/`FOV` читаются из
  `const` в момент использования.
- **Клиент**: не меняется. `const.SCALE`/`gs.render_scale`/`const.W`/`const.FOV`
  по-прежнему пишутся из `client/settings.py` и `client/client.py`; просто
  больше ни один потребитель не считает шаг колонки сам.
- **Протокол**: не меняется. **Сервер**: не меняется.
- **Тесты**: новый `smoke_depth_buffer.py`; обновляется один вызов в
  `smoke_perf.py`; регресс — `smoke_sector_render.py`, `smoke_framebuffer.py`,
  `smoke_framebuffer_tile.py`, `smoke_perf.py`, `smoke_dash_fx.py`,
  `smoke_resolution_controls.py`, `smoke_content_providers.py`,
  `tools/check_engine_imports.py`.
- **Риск**: минимальный, правка чисто локальная — индекс колонки считается по
  той же формуле, что и раньше, когда буфер и `SCALE` совпадали, поэтому на
  дефолтной конфигурации (`render_scale == SCALE`) кадр не меняется
  побайтово. Реально меняется поведение только там, где раньше был крэш или
  заведомо неверная колонка.
