# Design

## 1. Причина сбоя и граница починки

После слияния двух веток в `HEAD` оказались файлы разных поколений:

| Файл | Состояние в `HEAD` | Ожидание остального кода |
| --- | --- | --- |
| `server/lobby.py` | передаёт `tick_rate` в `GameWorld` | — |
| `server/game_world.py` | конструктор без `tick_rate` | получить и хранить частоту тиков |
| `server/server.py` | шлёт `tick_rate` в `handle_shoot` | частота есть и на мире |
| `shared/protocol.py` | пишет `tick_rate` в `HELLO_ACK` | `PROTOCOL_VERSION = 16` |
| `shared/version.py` | `PROTOCOL_VERSION = 15` | — |

Исключение возникает внутри обработчика надёжного `CREATE_PARTY`. Сетевой слой
ловит его общеобщим `except` для «битых датаграмм», поэтому клиент не получает
ни `JOIN_ACCEPT`, ни ошибки. Сокет остаётся открытым, остальные кнопки лобби
продолжают работать — отсюда и формулировка «кнопка не запускает матч».

**Решение:** не «добавить ещё один аргумент конструктору», а вернуть пару файлов
целиком к согласованной версии `b808b69`. Частота тиков — сквозной контракт
(`server/tick-rate`): она должна одинаково определять дедлайны игрового цикла,
кулдауны оружия, длительность дэша/задержек и packs в `HELLO_ACK`. Частичный
патч оставил бы мир с дефолтными 20 tps при сервере 40 tps и silent-отказами по
кулдауну.

**Альтернативы:**
- Добавить `tick_rate=None` в старый конструктор и игнорировать его: ломает
  настраиваемый FPS, который уже покрыт `smoke_server_fps.py`.
- Поднять версию протокола до 17: не решает ошибку создания партии и ломает
  совместимость с устоявшимся значением 16.
- Показывать ошибку в UI вместо починки: маскирует падение сервера, матч
  всё равно не запускается.

## 2. Клик по кнопке как регресс

`smoke_lobby_map_picker.py` проверял выбор карты и отправку `CREATE_PARTY` через
клавишу `P`. Пользователь жаловался именно на кнопку, а путь мыши идёт через
`GameClient._menu_events()` → `Renderer.to_canvas_pos()` → hit-тест
`LobbyScreen.create_btn`. Поэтому тест теперь делает реальный клик по
`create_btn` и дополнительно требует, чтобы на сервере появилась партия:

```python
await _pump(creator, _click(lb.create_btn), wait_game=True)
assert server.lobby.parties, "create button never reached the server"
```

Как и раньше, сценарий с обычным клиентом продолжает проверять `P`, так что
оба входа в `CREATE_PARTY` остаются покрытыми.

## 3. Зачем правились остальные тесты

Восстановление контракта `tick_rate` сделало явными несколько устаревших
допущений в smoke-файлах; все правки — только в тестовом коде:

- `smoke_items_mutation.py`: якорь мутации `_reset_items` потерял отступ 12
  пробелов (код внутри `if self.mode == 'pve'`); без этого мутация пропускалась
  как «anchor not found».
- `smoke_respawn.py`: `_apply_input` теперь читает `self.tick_interval`, поэтому
  вместо `None` передаётся минимальный stand-in с полем `tick_interval`.
- `smoke_projectiles.py`: FIRE — надёжный интент. Прямой `NetworkClient` без
  `start_reliable_loop()` копит исходящие пакеты в буфере; запуск насоса
  восстанавливает исходный путь `GameClient.run()`.
- `smoke_player_dash.py`, `smoke_sector_server.py`: зафиксированные номера
  протокола обновлены до 16 с пояснением, какой именно change добавил поле.

Отдельно в `smoke_sector_server.py` обновлено ожидание по врагам: активный
change `floating-platforms-unrestricted` разрешает врагам подниматься на
доступные плиты (`allow_platforms=True`, шаг не больше `STEP_HEIGHT`), а старый
тест требовал обратного. Теперь проверяются оба случая: низкая плита берётся
как опора, высокая — нет.

## 4. Что остаётся вне change'а

Не меняются протокольные структуры, механики, рендер и редакторы. Change
`sector-minimap-editor-fps-cleanup` остаётся реализованным, но не
заархивированным; главные спеки не обновляются до подтверждения пользователя.
