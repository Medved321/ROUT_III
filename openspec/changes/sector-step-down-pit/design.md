# Design

## Корень

Двусторонняя линия живёт в BSP как пара сегов-близнецов — по одному на каждую
грань. Оба попадают в одинаковый лист (портальная линия лежит на границе двух
листов, но её близнецы принадлежат тому листу, который режет линию), и обход
near→far может взять их в любом порядке. Каждый близнец по `_seg_wall_bands()`
рисует «свою» грань перепада и **двигает клипы колонок**.

Два следствия складываются в «дыры не видно»:

1. **Обратный близнец опускает `clip_bot` раньше видимого.** Тот из близнецов,
   чьё направление отвернуто от камеры, для ямы ставит `clip_bot` на свою
   линию пола — на экране это линия **дна** (его задний сектор — комната).
   `clip_bot[col] = yh = min(yf, flrob)` по линии пола переднего сектора. Спан
   пола ямы, который видимый близнец пушит позже по обходу near→far, имеет вид
   `[max(ceilt, yf_ямы), clip_bot]`, а `yf_ямы > yf_комнаты = yh`. Значит
   `y1 <= y0`, и `_push_flat()` его отбрасывает: пол комнаты непрерывно
   закрашивает пропасть (флаты рисуются в фазе B, а грани в фазе C затирают их
   только там, где построены).
2. **Порядок близнецов внутри листа не гарантирован.** Если обратный близнец
   приходит после видимого, перезаписывается уже обновлённый видимый клип;
   если до — дно отрезается. Оба порядка дают либо «дно невидимо», либо
   недетерминированный шов.

Нижняя грань при этом строится только в одном направлении: `if yfb < yf` —
ступень вверх. Для ямы выполняется `else` ветка `clip_bot[col] = yh` — без
полосы вообще.

## Решение

Две независимые правки в двусторонней ветке `_seg_wall_bands()`.

### 1. Обратная грань отсекается (back-face cull)

До построения граней:

```python
if scene.back_sec[li] >= 0:
    cross = (ax2 - ax1) * (py - ay1) - (ay2 - ay1) * (px - ax1)
    if cross >= 0.0:
        return
```

`cross((v2-v1),(cam-v1)) >= 0` — камера на **левой** стороне сегмента, то есть
сегмент смотрит в сторону от неё. Он не даёт ни полос, ни флатов, ни движения
клипов. Остаётся ровно один владелец колонки — близнец, обращённый к камере, —
и порядок пар больше не важен.

- Односторонние стены (`back_sec < 0`) близнецов не имеют и не отсекаются.
- Правило **winding-независимо**: «камера справа от направления сегмента».
  Формат не требует единой намотки — карты редактора держат внутреннюю
  конвенцию с другой стороны. Для симметричных/равнотекстурных проёмов выбор
  близнеца неразличим; для ямы и ступени остаётся та грань, что обращена к
  камере, — она и есть видимая.

### 2. Нижняя грань в обе стороны

Грань — вертикальная поверхность между двумя линиями пола. Единственное, что
различается для ступени вверх и ямы, — какой конец полосы ближе к горизонту:

```
yfb < yf  (ступень вверх)   полоса [yfb, yf];  clip_bot = max(yfb, yl)
yfb > yf  (яма)             полоса [yf, yfb];  clip_bot = max(yfb, yl)
```

Направление не проверяется: `lo = min(yf, yfb)`, `hi = max(yf, yfb)`, далее
обрезка открытым интервалом колонки и полоса в `bands`. `clip_bot` — по линии
пола **заднего** сектора, но не дальше уже существующего клипа колонки (дальний
лип не может переоткрыть пиксели, закрытые ближним сегом):

```python
lo = yfb if yfb < yf else yf
hi = yfb if yfb > yf else yf
if lo < yl:
    lo = yl
if hi > flrob:
    hi = flrob
if hi > lo:
    bands.append((col, lo, hi, low_tex, lv, tu,
                  ax1, ay1, ax2, ay2, t))
nb = yfb if yfb > yl else yl
clip_bot[col] = nb if nb < flrob else flrob
```

#### Тождество для ступени вверх

При `yfb < yf`: `lo = max(min(yf,yfb), yl) = max(yfb, yl) = r0` и
`hi = min(max(yf,yfb), flrob) = min(yf, flrob) = yh` — ровно прежние границы.
`clip_bot = min(max(yfb, yl), flrob)`: при `flrob > yfb` (ничего ближе не
закрыло колонку) это `max(yfb, yl)` как раньше; при уже закрытой колонке —
прежнее поведение, потому что полоса и клип-апдейт всё равно не выполнялись
для закрытой колонки. Значит кадр на ступенях вверх меняется лишь там, где
раньше обратный близнец уже двигал клип неправильно, а это и есть fix.

#### Сценарий Bc <= Sf не тронут

Условие `Bc <= Sf` (потолок заднего сектора не выше пола переднего) попрежнему
схлопывает `two` в сплошную стену — между секторами есть порода, проёма нет.
`upper` не меняется вовсе (non-goal).

## Почему полосу достаточно, пол не нужно перерисовывать

Пол комнаты пушится как `[max(ceilt, yf), flrob]` — до обновления клипа, то
есть уже покрывает и строки ямы. Ничего отменять не нужно: стены рисуются в
фазе C **после** флатов (фаза B) и затирают пол ровно на своей полосе. Грань —
обычная полоса в `bands`, поэтому порядок фаз работает на неё тем же путём,
что и на ступень вверх.

## Проверка

`smoke_sector_pits.py` (задачи 2.1–2.6) рендерит «комната + провал» в трёх
конфигурациях (глубина 64 / ступень 16 / контроль без перепада), плюс ступень
вверх и вариант с ближней стеной перед кромкой:

- **дно ямы видно**: спанов пола ямы > 0 и на кадре есть пиксели её текстуры;
- **глубина видна**: кадр для −64 отличается от кадра для −16 (раньше был
  тождественно равен);
- **грань на месте**: полоса `lower` присутствует и лежит между линиями полов;
- **контроль без перепада**: граней нет, а пол сектора одной высоты виден в
  кадре своей текстурой — обратный близнец не уводит дно за границу (вместо
  byte-равенства эталону HEAD: равнополый проём корректно показывает пол
  внутреннего сектора, чего старый рендер не делал);
- **кромка за ближней стеной**: не рисуется и не двигает клип закрытой колонки.

Тождество ступени вверх и отсутствие регрессов — `smoke_sector_render.py`,
`smoke_sector_flats.py`, `smoke_tiers.py`, `smoke_bsp_render.py` (там заодно
проверяется, что обратный близнец не даёт полос).

## Альтернативы

- **Симметричная формула полосы без отсечения обратного близнеца.** Отвергнуто:
  кромка ямы появилась бы, но дно по-прежнему отрезалось бы `clip_bot`
  обратного близнеца (мутационная проверка падает: верх ступени без отсечения
  невидим).
- **Отрисовать яму отдельной сущностью/эффектом.** Отвергнуто: дыра — это
  обычная двусторонняя линия в существующей модели, новый примитив и новая
  настройка качества не нужны, а `lower` уже назначается редактором.
- **Поменять знак сравнения на `yfb != yf`, оставив две ветки.** Отвергнуто:
  две почти одинаковые ветки расходятся при `yh`-обрезке и это уже источник
  бага; одна формула симметрична и доказанно тождественна старой на ступени
  вверх.
- **Требовать единой намотки двусторонних линий вместо отсечения.** Отвергнуто:
  обратная грань осталась бы в рендере, а разный формат карт (редактор/ручные
  карты) хранит намотку независимо; правило «камера справа» решает задачу без
  смены формата.
- **Схлопнуть `Bc <= Sf` в «дыру».** Отвергнуто: это не дыра, а порода между
  секторами; DOOM рисует там сплошную стену, и врать здесь — значит показать
  игроку несуществующий проём.
- **Трогать верхнюю грань заодно.** Отвергнуто: та же асимметрия, но к жалобе
  не относится и ломает работающие случаи «потолок ниже»; вынесено в
  non-goals.
