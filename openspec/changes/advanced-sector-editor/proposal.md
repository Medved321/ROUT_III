## Why

Текущий редактор карт работает только «тайлами» (плитка 64×64), а секторный
рендер (`_render_sector_scene`) существует, но не используется: он наивный
(O(колонок × линий) в чистом Python, `transform.scale`+`tint`+`blit` на каждую
колонку и аллокации) и не потянет настоящие секторные карты DOOM-уровня.
Нужен полноценный секторный редактор и рендер уровня DOOM 1, который летает в
60 FPS даже на машинах в два раза слабее — это требование ко всей игре.

## What Changes

- **Новая секторная модель карты** в `shared/sector_map.py`: вершины, лайндефы
  (одно/двусторонние, спецэффекты, теги), сайдедефы (текстуры
  верх/низ/середина, смещения), сектора (высоты пола/потолка, флаты, свет),
  вещи (спавны игроков, враги, предметы). Хранение `maps/*.json`
  (дискриминатор формата `"format": "sector"`), валидация при загрузке.
- **Полный Doom-style 2D-редактор** (новый экран, доступен из лобби и из
  текущего редактора через переключение режима «Тайлы / Сектора»): работа с
  вершинами/линиями/секторами/вещами, замыкание секторов из контура,
  разрезание линии, сетка-привязка, панель свойств, палитра текстур/флатов/вещей,
  undo, «▶ Играть» (F5). Сам редактор тоже обязан держать 60 FPS на слабом железе.
- **Рендер секторных сцен уровня DOOM 1** (замена `_render_sector_scene`):
  пространственная индексация линий (сетка ячеек + DDA-проход как сейчас по
  тайлам), по-колоночные «порталы» с клиппингом по верхнему/нижнему краю
  (окна, ступени, двери), предрассчитанные уровни освещения поверхностей
  вместо `tint`-наложения на каждую колонку, рендер во внутренний буфер
  пониженного разрешения с единственным `scale` за кадр, флаты с перспективой
  по уровням качества.
- **Минимальная серверная поддержка**: сервер принимает секторные карты в
  `CREATE_PARTY`/`JOIN_ACCEPT` (байт формата карты — **BREAKING** для протокола,
  поднимаем `PROTOCOL_VERSION`), валидирует их, размечает столкновения
  (растеризация границ одно-сторонних линий) и спавнит игроков по вещам
  «player1». Локальная игра на своей машине работает как раньше.
- **Импорт тайловой карты в секторную**: базовый конвертер (связные области
  пустых клеток → сектора, стены → одно-сторонние лайндефы, одинаковая высота)
  — чтобы старые карты не пропали.

**Non-goals** (отдельные изменения в будущем, сейчас осознанно не делаем):

- **Мультиплеер секторных карт по сети** — оптимизация передачи больших карт,
  синхронизация и перфоманс с несколькими удалёнными клиентами. Этот change
  делает карту играбельной локально (один игрок на своей машине, связка
  клиент → локальный сервер как сейчас).
- Динамические лифты/платформы по тегам и скриптовая логика дверей по тегам
  (двери-«сьюты» с анимацией — только базовая закрытая дверь).
- Полная автогенерация секторов из произвольных тайловых карт (сложное
  сшивание секторов) — только базовый конвертер выше.
- Рендер стеков/спрайтов через BSP: остаёмся на по-колоночной трассировке,
  но доводим её до уровня оптимизации DOOM 1.

## Capabilities

### New Capabilities

- `map/sector-format`: модель данных секторной карты (вершины, лайндефы,
  сайдедефы, сектора, вещи), JSON-сериализация/валидация, служебные функции
  (принадлежность точки сектору, спавны, индекс границ для столкновений).
- `editor/sector-editor`: полноценный Doom-style 2D-редактор секторных карт
  (инструменты, свойства, палитры, undo, сохранение/загрузка, «▶ Играть») с
  гарантией 60 FPS.
- `renderer/sector-renderer`: оптимизированный рендер секторных сцен уровня
  DOOM 1 (пространственная индексация, порталы и клиппинг, уровни света,
  внутренний буфер низкого разрешения, флаты) с жёстким бюджетом 60 FPS.
- `server/sector-maps`: приём, валидация и работа сервера (столкновения,
  спавны, взаимодействия) с секторными картами для локальной игры.

### Modified Capabilities

- нет (существующих спецификаций, чьи требования меняются, нет — изменения
  добавляют новые возможности, а не меняют поведение текущих).

## Impact

- **Новые модули**: `shared/sector_map.py` (модель+валидация+конвертер),
  `client/engine/sector_editor.py` (модель редактора), новый экран
  `client/sector_editor_screen.py`; `client/engine/sector_render.py` (новый
  бэкенд рендера секторных сцен).
- **Протокол (`shared/protocol.py`, `SPEC.md`)**: байт `map_format` в
  заголовках `CREATE_PARTY` (0x0A) и `JOIN_ACCEPT` (0x04) — **BREAKING**,
  `PROTOCOL_VERSION` в `shared/version.py` поднять; карты сектора передаются
  как JSON-байты через уже существующий надёжный канал с фрагментацией
  (`MAX_FRAGMENT_PAYLOAD`), ограничение 64×64 тайлов к секторным картам
  неприменимо (снимается только для формата sector).
- **Сервер**: `server/server.py` (валидация карты), `server/game_world.py`
  (интерфейс `GameMap` → общий интерфейс карты: `is_wall_px/can_move_px/
  has_los_px/spawn`), `server/network.py`, `server/lobby.py`.
- **Клиент**: `client/client.py` (`_editor_loop`, переключение режима редактора,
  создание партии с секторной картой), `client/engine/game_state.py` (загрузка
  `SectorMap` в `sec_*`-поля), `client/lobby_screen.py` (индикатор типа карты),
  `client/engine/rendering.py` (разветвление `gs.sector_mode` на новый бэкенд).
- **Рендер целиком обязан не регрессировать ниже 60 FPS** на машинах в два
  раза слабее: бюджетные требования закрепляются в `renderer/sector-renderer`
  и перекликаются с `client/performance` (адаптивное качество из
  `low-end-performance` доводится до секторного пути — внутреннее разрешение и
  уровень флатов как параметры качества).
- **Версии**: для секторного формата карты добавляем собственный номер
  версии; тайловые карты и их формат не меняются.
