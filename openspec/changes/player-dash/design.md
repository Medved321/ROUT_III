# Design

## Контекст

Движение сейчас устроено так:

| слой | где | что |
|---|---|---|
| ввод | `client/input_handler.py:35-42` | `move_x`, `move_y` из WASD/стрелок |
| сеть | `client/client.py:479` → `client/network_client.py:234` | `PLAYER_INPUT` 25 раз/с, отдельно от кадров |
| авторитет | `server/server.py:288-293` | `vel.dx/dy` = направление × `MOVE_SPEED_PX * TICK_INTERVAL` |
| интеграция | `server/game_world.py:171-182` | раз в тик, посеговое скольжение, `vel` обнуляется |
| коллизия | `can_move_px(x, y, r)` | конечная точка + радиус, оба формата карт |

Клиент **не предсказывает позицию**: `client/client.py:659` каждый кадр берёт
`local_x/local_y` из авторитетного состояния. Предсказывается только угол
(`local_angle` + сверка с сервером). Это ключевой факт для дэша: новая механика
не требует клиентской логики позиции вообще.

## Решения

### 1. Протокол: байт флагов, а не отдельный байт «dash»

```python
INPUT_FLAG_DASH = 0x01
struct.pack("!bbfBBB", move_x, move_y, angle, shoot, weapon_id, flags)
```

Байт булевых занял бы столько же места, но флаг-битфилд переживает следующую
механику (рывок с двойным нажатием, спринт) без нового изменения протокола.
`PROTOCOL_VERSION` поднимается 6 → 7: `struct.unpack` на старом 8-байтном
пакете бросил бы исключение, а handshake уже умеет отвергать несовместимого
клиента понятным сообщением (`client/network_client.py:118-125`) — это
правильный канал, дублировать его не нужно.

Клиент шлёт **импульс**: `dash_pressed` живёт один кадр, `_input_snapshot`
сбрасывает `_dash_pending` при первом использовании. Удержание пробела не
повторяет дэш — ровно как `shoot_pressed` для огня.

### 2. Условия старта: нужен ввод движения

```python
if want_dash and (move_x or move_y) and dash.cooldown <= 0:
    dash.ticks = DASH_TICKS
    dash.cooldown = DASH_COOLDOWN_TICKS
```

- **Нужен ввод движения.** Направление дэша = направление ввода, то есть
  ровно то, что уже приходит в `PLAYER_INPUT`. Не вводим второе правило
  («рывок по взгляду, если стоишь») — две модели направления в одной механике
  дают плохо читаемое поведение.
- **Без ввода запрос игнорируется и кулдаун не тратится.** Иначе игрок, который
  нажал пробел до начала ходьбы, «съедал» бы кулдаун вхолостую.
- **Кулдаун выставляется вместе со стартом.** Это делает операцию
  идемпотентной: повторная доставка пакета (у надёжного канала бывают
  дубликаты) не удваивает рывок, отдельный edge-detection на сервере не нужен.

### 3. Числа

| величина | значение | обоснование |
|---|---|---|
| `DASH_SPEED_MULT` | 2.5 | 480 px/с = 7.5 тайла/с против 3 тайла/с ходьбы — читаемый скачок, но не телепорт |
| `DASH_TICKS` | 5 | 250 мс → 120 px ≈ 1.9 тайла: пересечь комнату и уйти от выстрела, не проскочив сквозь врага |
| `DASH_COOLDOWN_TICKS` | 30 | 1.5 с — два-три рывка на боевой контакт, без спама |

Все три живут в `server/game_data.py` рядом с `MOVE_SPEED_PX` и выражены в
тиках: сетевого таймера дэша нет, сервер и так тикает 20/с.

### 4. Подшаг делает коллизию независимой от скорости

`_apply_movement()` проверяет **только конечную точку** шага, поэтому он
корректен лишь пока шаг не длиннее `2 * radius` (32 px при `PLAYER_RADIUS = 16`):
чтобы оказаться по другую сторону лайндефа, игрок должен приземлиться дальше
чем на `radius` за ним, а начать он может не ближе чем за `radius` до него.

- Шаг дэша = `192 * 2.5 / 20` = **24 px < 32**, то есть *при текущих числах*
  фазовый переход невозможен и подшаг ничего не спасает.
- Но это числовая ловушка: любое будущее ускорение (`DASH_SPEED_MULT` ≥ 3.4) или
  сущность с меньшим радиусом её нарушит, и туннель станет реальным багом,
  который за месяц никто не свяжет с дэшем.

Поэтому шаг длиннее порога делится на равные части, и движение останавливается
на первой заблокированной:

```python
MAX_MOVE_STEP_PX = MOVE_SPEED_PX * TICK_INTERVAL   # 9.6 px
```

Порог **равен** шагу обычной ходьбы, поэтому:
- ходьба: подшагов 0, ровно одна проверка `can_move_px()` на ось — как сегодня,
  ни одного лишнего вызова в горячем пути (это 20 вызовов/с на игрока);
- дэш 24 px: 3 подшага по 8 px — 3 проверки вместо одной.

Оси остаются независимыми (скольжение вдоль стены сохранено): подшаг применяется
внутри каждой оси, а не к вектору целиком.

**Отвергнуто:** ограничить скорость дэша так, чтобы шаг не превышал ~9 px, то
есть отказаться от ускорения. Тогда дэш станет «длинным шагом» без
собственной скорости — теряется весь смысл.
**Отвергнуто:** брать пошаговую проверку только во время дэша. Тогда у
остальных сущностей (враги, снаряды) появился бы другой коллизионный код, а
поведение игрока зависело бы от флага.
**Отвергнуто:** вписывать «2 * radius» в константы дэша (держать скорость ниже
предела). Это переносит то же числовое ограничение в настройку баланса, где его
невозможно не нарушить молча.

### 5. `state = 3` — видимость дэша без роста пакета

`world_state` уже несёт у игрока байт `state` (`0=alive, 1=dead, 2=shooting`),
который **сейчас никто не читает** (в блоке «other players» рендера его нет).
Поэтому дэш получает значение 3 без изменения размера записи игрока (21 байт).
Приоритет у дэша над стрельбой: это более заметное событие, а состояние
стрельбы на других игроков всё равно не рисуется.

Рендер при `state == 3` берёт более светлую shirts-палитру. Это единственная
визуальная обратная связь; полноценные частицы/след — отдельный ассет-проход.

## Что НЕ меняется

- Формат карт (`.mt1`, `.json`, `.mts`) и правила проходимости, включая
  `STEP_HEIGHT`: дэш не отменяет ступени и не проходит сквозь них.
- `Velocity`/`Position`/`Collider`, посеговое скольжение, ходьба.
- Огонь, оружие, кулдауны, `FIRE`, надёжный канал.
- Клиентская предсказация позиции (её нет).
- Столкновения игрок-игрок (их нет и раньше; дэш их не вводит).

## Проверка

`smoke_player_dash.py` (headless, без сокетов):

1. **Раскладка протокола.** `flags` переживает round-trip, бит дэша не
   пересекается с `shoot`/`weapon_id`; длина 9 байт; `PROTOCOL_VERSION == 7`.
2. **Старт и таймеры.** Запрос с вводом движения и без кулдауна → `ticks = 5`,
   `cooldown = 30`; повторный тот же запрос (имитация дубликата) не продлевает.
3. **Требуется движение.** Запрос без ввода движения не стартует дэш и не тратит
   кулдаун.
4. **Скорость.** На тике дэша скорость ровно в `2.5` выше обычной; через
   `DASH_TICKS` тиков — снова обычная; кулдаун истекает за `30` тиков.
5. **Коллизия не зависит от скорости.** Секторная карта со сплошной линией
   в 1 тайл: дэш-шаг (24 px) не пересекает её ни из одной стартовой позиции;
   шаг длиннее `2 * radius` (40 px), который одна проверка конечной точки
   пропустил бы насквозь, подшаг останавливает. При отладке подшагов тесты
   5a/5b/6 падают.
6. **Обычная ходьба не изменилась.** Число вызовов `can_move_px()` на тик
   ходьбы = 2 (по одному на ось), как до подшага; на тике дэша > 2.
7. **`state = 3` только во время дэша**, и обратно в 0/2 после.
