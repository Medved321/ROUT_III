# Tasks — music-playback

## 1. Модуль `client/music.py`

- [x] 1.1 `_ensure_mixer()`: явная `pygame.mixer.init(frequency=44100, size=-16,
      channels=2, buffer=512)`, одна запасная попытка `22050`/mono, запоминание
      отказа без повторов. Проверка: на машине с подменённым `mixer.init`,
      падающим всегда, вызов делает ровно 2 попытки и возвращает «тихо»
- [x] 1.2 `scan_tracks()`: каталог `Path(__file__).resolve().parent.parent /
      "music"`, расширения `.ogg/.mp3/.wav/.flac/.opus`, префикс `menu_*` — в
      группу меню, остальное — в группу партии, сортировка по имени.
      Проверка: `smoke_music.py` на временном каталоге из 4 файлов (2 `menu_*`,
      2 прочих, 1 `.txt`) ждёт 2+2 и игнорирование `.txt`
- [x] 1.3 `_play_group()`: выбор следующего трека без повтора только что
      закончившегося при группе больше одного трека, повтор по кругу при одном;
      нечитаемый трек помечается и больше не выбирается; пустая группа — тишина.
      Проверка: `smoke_music.py` на 100 прогонах без мгновенного повтора при
      группе из 3 треков и без повторов при группе из 1
- [x] 1.4 Фоновая `asyncio`-задача с опросом `music.get_busy()` раз в 50 мс,
      переход на следующий трек по концу текущего, остановка на
      `client.running = False`. Проверка: тест с подменённым `get_busy()`
      (сначала True, потом False) видит ровно один переход и не грузит трек
      повторно
- [x] 1.5 Публичный API `set_context("menu"|"game")`, `set_volume(v)` с
      зажимом в 0..1, `start()`, `stop()`; громкость 0 не мешает загрузке трека.
      Проверка: тест пишет `set_volume(0)` при играющем треке и убеждается,
      что `load()` не вызывался
